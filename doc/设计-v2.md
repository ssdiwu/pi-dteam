## 偏离设计的地方

### 偏离 1：planner 不调 LLM tool calling，改用规则判断

**原设计**：用 typebox 定义 plan 工具，让 LLM tool calling 返回结构化 ExecutionPlan。

**实际**：planner 先用关键词正则做规则判断（零 LLM 成本），复杂情况才调 LLM 拿 JSON。

**原因**：
- MiniMax-M3 tool calling 不稳定（plan 工具 schema 复杂，经常返回文本而非工具调用）
- JSON 模式更可靠
- 规则判断覆盖 80% 场景，零成本

**代码**：`src/planner.ts:quickRuleBasedPlan`

### 偏离 2：递归分解未接入 build 步骤

**原设计**：
> 递归分解不是被替代，而是嵌套在 plan 的 build 步骤里。
> plan step: build → brancher.decide() → decompose | execute

**实际**：orchestrator 直接 `leaf.execute()` 跑 build 任务，没调 `brancher.decide()`。

**原因**：
- 实测中 LLM 自身能在多轮里搞定复杂任务（用 edit/write 工具）
- 接入 brancher 需新增 tool calling + 错误处理 + pool 池化任务
- 不是当前架构必须

**影响**：
- 复杂 build 任务完全依赖 LLM 自己的能力
- 没有"如果太大就拆"的安全网
- 极大任务可能一次跑不完

### 偏离 3：UI 显示简化

**原设计**：

**实际**：

## 二维编排模型（最终版）

### 维度一：组织形式

| 形式 | 节点类型 | 含义 | 代码位置 |
|------|---------|------|---------|
| `solo` | 叶子 | 单步执行 | `executeSteps(..., "serial")` 只跑 1 个 |
| `chain` | 分支 | 串行，前一步输出注入下一步 | `executeSteps(..., "serial")` 跑 N 个 |
| `team` | 分支 | 并行，分批（每批 ≤ 3） | `executeSteps(..., "parallel")` |

### 维度二：执行策略

| 策略 | 含义 | 循环 | 代码位置 |
|------|------|------|---------|
| `direct` | 跑一次出结果 | 无 | `runDirect` |
| `build_check` | build → check → 修 → 再 check | 最多 3 轮 | `runBuildCheck` |
| `adaptive` | 执行 → 评估 → 调 → 再评估 | 最多 5 轮 | `runAdaptive` |

### strategy 在 per-step，不是 per-plan

每个 step 独立选策略。`ExecutionPlan` 顶层没有 `strategy` 字段。

```typescript
interface ExecutionPlan {
  mode: "solo" | "chain" | "team"   // 维度一：组织形式
  steps: PlanStep[]                  // 步骤列表
  reason: string                     // 规划的简短说明
}

interface PlanStep {
  role: RoleName
  task: string
  strategy: Strategy                // 维度二：每个 step 独立
  files?: string[]
}
```

## 三阶段流水线

```
orchestrator.run(goal, ctx)
  │
  ├─ Phase 1: Plan
  │     planner.plan(goal, ctx) → ExecutionPlan
  │     ├─ 1. 规则判断 quickRuleBasedPlan（5 个 regex 匹配）
  │     └─ 2. LLM 兜底（复杂情况，调 LLM 拿 JSON）
  │
  ├─ Phase 2: Execute
  │     按 mode 分发：
  │     ├─ solo  → runStep(steps[0])
  │     ├─ chain → 串行 runStep(prevOutput 注入)
  │     └─ team  → 分批 Promise.all（每批 ≤ 3）
  │
  │     每个 step 按 strategy：
  │     ├─ direct      → leaf.execute()
  │     ├─ build_check → build → check 循环
  │     └─ adaptive    → 执行 → 评估循环
  │
  └─ Phase 3: Report
        汇总 StepResult[] → RunResult
```

## 数据流

```
goal (string)
  ↓ planner
ExecutionPlan { mode, steps: [{ role, task, strategy }] }
  ↓ orchestrator
每 step → leaf.execute(role, task, ctx, goal)
  ↓
StepResult { role, task, strategy, status, output, rounds? }
  ↓
RunResult { status, goal, plan, steps, summary }
  ↓
JSON string → 返回给 LLM
```

## 关键不变量

1. **team 并发度 ≤ 3**：避免撞 API 限流
2. **build_check 轮数 ≤ 3** / **adaptive 轮数 ≤ 5**：防止死循环
3. **chain 中 step 失败 → 终止**：保留已完成结果
4. **build 唯一能改代码**：`getRoleTools("build")` 含 edit，其他不含
5. **MiniMax-M3 优先**：找不到自动降级到 M2.7
