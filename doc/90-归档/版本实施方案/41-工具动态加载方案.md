# 工具动态加载方案

> **版本归属**：0.4.1（已发布）
> **状态**：**已实现为方案 D**（主 LLM 传入可用工具列表）。早期方案 C（`discoverAndLoadExtensions` 文件系统发现）经实操测试**证明不可行**——pi 加载的扩展不一定在文件系统，已废弃。
> 讨论时间：2026-06-06
> 与 `../20-能力参考/21-扩展API参考.md` 配套：那份是 Pi 扩展 API 参考表，这份是 D 的设计稿。

## 一句话总结

dteam 工具的"可用工具"列表**由主 LLM 调用 dteam 时通过 `availableTools` 参数显式传入**。dteam 不再做"自己猜"——它信任调用方。

---

## 演进历史

### 方案 C（已废弃）：discoverAndLoadExtensions 发现

**思路**：dteam 调 `discoverAndLoadExtensions([], cwd)` 扫盘枚举已加载扩展，列给 planner LLM 选。

**实操测试结果**（2026-06-06）：
- `discoverAndLoadExtensions([], cwd)` → 0 extensions
- `discoverAndLoadExtensions([], cwd, agentDir=~/.pi/agent)` → 0 extensions
- `~/.pi/agent/extensions/` → 空目录
- 但 pi 主会话**能调** tinyfish_search（运行时动态加载）

**根因**：`discoverAndLoadExtensions` 是"扫盘找可加载的扩展"，**不是**"枚举已加载的扩展"。两个 API 名字很像，语义不同。

**结论**：方案 C 失败，回退。但保留 `PlanStep.tools?` 字段作为 v1.1 接口占位（一旦 pi 出"枚举已加载工具" API，能直接接上）。

### 方案 D（当前）：主 LLM 显式传入

**思路**：dteam 工具 schema 加 `availableTools?: string[]` 参数。主 LLM 调 dteam 时，把自己看到的工具名列表传进去。dteam 用这个列表做"工具宇宙"。

**为什么支持所有用户**：
- 用户 A 装了 tinyfish → 主 LLM 知道有 `tinyfish_search` → 传 `availableTools` 包含它
- 用户 B 装了 pi-web-access → 主 LLM 知道有 `web_search` → 传 `availableTools` 包含它
- 用户 C 啥都没装 → 主 LLM 传内置工具列表 → dteam 仍能干活（不联网而已）
- **dteam 不依赖任何文件系统状态**

## 方案 D 的具体形态

### 数据流

```
主 LLM 调 dteam
  ↓
  dteam(
    action="run",
    goal="Search the web for Node.js LTS",
    availableTools=["read","write","bash",...,"tinyfish_search","tinyfish_fetch"]  // 主 LLM 传
  )
  ↓
  index.ts execute() 把 availableTools 挂到 runCtx.dteamAvailableTools
  ↓
  orchestrator.run(goal, runCtx)
  ├─ plan(goal, ctx, ctx.dteamAvailableTools)
  │   ├─ quickRuleBasedPlan 命中 → return（quick path 走 ROLE_DEFAULTS）
  │   └─ LLM 路径
  │       ├─ systemPrompt 注入"- name"清单
  │       ├─ LLM 返回 JSON（含 step.tools）
  │       ├─ intersect(step.tools, availableToolNames) 过滤掉不存在的
  │       └─ 透传到 step.tools
  └─ executeSteps → strategies → leaf.execute(..., step.tools)
      └─ createWorkerSession({ builtInTools: step.tools })
```

### 行为契约

| 场景 | 行为 |
|------|------|
| 主 LLM 传 `availableTools: ["a", "b", "c"]` | dteam 用此集合做工具宇宙 + systemPrompt 注入 + intersect 验证 |
| 主 LLM 不传 | **fallback 到 ROLE_DEFAULTS**（v0.4.0 行为保留，systemPrompt 写"（未提供；不填则用角色默认工具）"） |
| 主 LLM 传 `[]`（空数组） | 等同不传 |
| 主 LLM 传但不是数组（如 string） | orchestrator 视为 undefined，fallback |
| LLM 填了 `step.tools` 但有拼写错 | intersect 过滤，全空就降级（不设 tools 字段） |
| LLM 没填 `step.tools` | 走 ROLE_DEFAULTS |
| chain / team 模式 | step.tools 仍透传（已测） |

### intersect 规则（关键）

```ts
const tools = Array.isArray(s.tools)
  ? s.tools
      .filter((t): t is string => typeof t === "string")
      .filter(t => availableToolNames.size === 0 || availableToolNames.has(t))
  : undefined;
```

**核心细节**：`availableToolNames.size === 0` 时跳过 intersect——这是 v0.4.0 兼容路径（不传 availableTools 时 LLM 填啥就用啥，不做验证）。

#### Test 3 成功验证（2026-06-07）

**场景**：主 LLM 调 dteam，goal="Search the web for 'Node.js LTS current version 2026' and write the result to /tmp/dteam-test3.txt"，传 availableTools 包含 tinyfish_search / tinyfish_fetch / read / write / bash / grep / find / ls / dteam / mcp / marketplace_*。

**完整链路验证**：
1. 主 LLM 传 availableTools → index.ts 挂到 runCtx.dteamAvailableTools ✓
2. orchestrator.run 读 ctx.dteamAvailableTools → 透传给 plan() ✓
3. planner LLM 看到 systemPrompt 里的工具清单 ✓
4. LLM 选 step.tools = ["tinyfish_search", "read", "write"] ✓
5. intersect 验证通过（都在 availableTools 里）✓
6. step.tools 透传到 leaf.execute(..., step.tools) ✓
7. createWorkerSession 调 loadConfiguredPackages(cwd) → 读 ~/.pi/agent/settings.json 的 packages → 过滤非 npm/git/http 项 → 解析相对路径为绝对路径 → 调 resolvePackageExtensions 读 package.json 的 pi.extensions 字段 → 得到 /Users/diwu/Documents/codes/Githubs/pi-tinyfish/extensions/index.ts ✓
8. discoverAndLoadExtensions([该路径], cwd) 加载 pi-tinyfish 扩展 ✓
9. makeResourceLoader(systemPrompt, extensionsResult) 注入到 worker session ✓
10. createAgentSession({ tools: step.tools, resourceLoader }) 创建 worker session，tinyfish 扩展可用 ✓
11. worker LLM 看到 tinyfish_search 工具 → 调用 → 真实搜索 nodejs.org ✓
12. 搜索结果写到 /tmp/dteam-test3.txt ✓

**产物验证**：文件开头是 "Search Query: ... / Search Date: 2026-06-07 / Sources: https://nodejs.org/dist/index.json" + 真实数据（v24 Krypton / v24.16.0 / 2026-05-21），不再是 "No live web search tool was available"。

**结论**：方案 D + resource-loader 修复使 dteam 能用主会话自定义路径加载的扩展（pi-tinyfish）。其他用户只要按相同方式在 settings.json.packages 里加自己的扩展，dteam 就能使用。

## 已知 v1.1 改进项

- **build_tools / check_tools 拆分**：build_check / adaptive 当前共用 `step.tools`，v1.1 拆成两个字段
- **description 传递**：当前 `availableTools` 是 `string[]`（只传 name），v1.1 可考虑 `Array<{name, description}>` 让 LLM 更好理解
