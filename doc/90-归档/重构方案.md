# dteam v1 重构方案

> 状态：探索阶段（基于 `src/orchestrator.ts` / `src/leaf.ts` / `src/session.ts` / `src/signals/index.ts` 现状）
> 目标：在不破坏对外行为（`index.ts` 入口、信号协议、`pi` 扩展点）的前提下，偿还 v1 留下的技术债。
> 范围：仅 v1（不涉及 v2 的 brancher 重做、动态角色、异步多 run 等远期目标）。

## 2. 推荐的拆分 / 合并 / 重命名

### 2.1 总体策略

- **按"职责"拆，保留"流程"在 orchestrator**：把横切关注点（信号订阅、UI 同步、help 自愈、链式继承）抽成命名清晰的辅助函数/小类，主流程只剩 5–7 个步骤。
- **引入 `config.ts` 集中常量**：所有 magic number / 路径 / 超时统一从 `src/config.ts` 取。
- **`session.ts` 拆成 4 个文件**：每个文件 1 个职责，主文件 `session.ts` 变薄到 50 行协调。
- **`tools.ts` 拆成 4 个类型文件**：消除 200 行的"杂物间"。
- **不引入新的运行时依赖**：v1 阶段只用 `node:` 内置 + 现有 peer deps。

### 2.2 详细拆分

#### A. `src/orchestrator.ts` → 1 主 + 4 辅

```
src/
├── orchestrator.ts          (主流程，run() 缩到 <50 行)
└── orchestrator/
    ├── signal-handlers.ts   (4 路 listener：progress/found/blocked/help)
    ├── help-self-heal.ts    (help 自愈回路：派 explore 补充 + 升级人类)
    ├── peer-forwarder.ts    (forwardSignalToPeers + injectionQueue 写入)
    └── history-context.ts   (buildHistoryContext)
```

**重命名建议**：
- `runBuildCheck` → `runStepWithBuildCheckStrategy`
- `runAdaptive` → `runStepWithAdaptiveStrategy`
- `runDirect` → `runStepWithDirectStrategy`
（命名统一前缀，便于 IDE 跳转）

**契约变化**：
- `run(goal, ctx)` 签名不变（保持 `index.ts` 入口稳定）
- 内部不再直接调用 `uiStore.*`，统一走 `reporter` 接口（见 2.2-D）

#### B. `src/session.ts` → 1 主 + 4 辅

```
src/
├── session.ts                (createWorkerSession 入口，<60 行)
└── session/
    ├── resource-loader.ts    (makeResourceLoader)
    ├── role-config.ts        (ROLE_DEFAULTS + getRoleTools)
    ├── role-prompt.ts        (loadRolePrompt 异步化)
    ├── model-resolver.ts     (resolveModelStr + pickAvailableModel)
    └── signal-tool.ts        (makeWorkerSendSignalTool 抽出，便于单测)
```

**关键改动**：
- `ROLE_DEFAULTS` 改为 `BASIC_TOOLS` + `role-specific` 两层组合，消除 5 处重复：

  ```ts
  const BASIC_TOOLS = ["read", "bash", "grep", "find", "ls"];
  const DTEAM_TOOLS = ["worker_sendSignal", "reference_architecture"];
  const ROLE_DEFAULTS: Record<RoleName, RoleConfig> = {
    explore: { tools: [...BASIC_TOOLS, "tinyfish_search", "tinyfish_fetch", ...DTEAM_TOOLS], ... },
    design:  { tools: [...BASIC_TOOLS, "write", ...DTEAM_TOOLS], ... },
    // ...
  };
  ```

- `loadRolePrompt` 改 `fs/promises.readFile` 异步；fallback 链增加 `~/.dteam/agents/${role}.md` 与 `package.json` 声明的 `agents` 字段。
- `pickAvailableModel` 的 `console.error` 改为 `onWarning?: (msg: string) => void` 回调。

#### C. `src/leaf.ts` → 拆出 worker 工具

```
src/
├── leaf.ts              (execute 主流程，<80 行)
└── leaf/
    ├── worker-id.ts     (生成器单点：nextWorkerId(role, runId))
    └── supplement.ts    (waitForSupplement + MAX_HELP_ROUNDS 配出)
```

**关键改动**：
- `ctx: any` 收窄为 `Pick<PiExtensionContext, 'dteam' | 'cwd' | 'model' | 'modelRegistry'>`。
- `pendingSupplements` 改为 `Map<workerId, Array<(v) => void>>`（队列式），覆盖 L-4。
- `setTimeout` 引用保存在闭包内，resolve 时主动 `clearTimeout`。
- `extractLastText` 升级为 `extractFinalText`：在最后一个无工具调用的 assistant message 中取。

#### D. 引入 `src/reporter.ts`（解耦 UI）

```ts
// src/reporter.ts
export interface Reporter {
  startRun(goal: string): void;
  addWorker(w: WorkerView): void;
  updateWorker(id: string, patch: Partial<WorkerView>): void;
  addSignal(workerId: string, sig: SignalView): void;
  addStrategy(s: StrategyView): void;
  finishRun(): void;
}

// 默认实现：包装 uiStore
export const defaultReporter: Reporter = { /* delegate to uiStore */ };

// 调用方：ctx.reporter ?? defaultReporter
```

把 O-3 的 8+ 处 `uiStore.*` 改为 `reporter.*`，后续替换 UI 不动业务。

#### E. 引入 `src/config.ts`（集中常量）

```ts
// src/config.ts
export const DTEAM_CONFIG = {
  team: { batchSize: 3 },
  buildCheck: { maxRounds: 3 },
  adaptive: { maxRounds: 5 },
  leaf: { maxHelpRounds: 3, supplementTimeoutMs: 60_000 },
  agentPaths: ["agents", "~/.dteam/agents"],
  // 后续可被 ctx.config 覆盖
} as const;
```

消除 O-7 + L-2。

#### F. `src/tools.ts` 拆分

```
src/types/
├── signal.ts       (SignalType, Signal, SignalPayload, 4 个 *Payload)
├── run.ts          (WorkerRun, WorkerRunStatus, IRunsStore)
├── role.ts         (RoleName, RoleConfig)
└── context.ts      (DteamContext, PendingSupplementsMap)
```

每个文件 <60 行，消除 X-1。

#### G. `src/signals/index.ts` → 改名 `src/signals.ts`

仅 23 行的 re-export 直接改名为 `signals.ts`，避免 `index.ts` 在某些配置下的特殊行为。或保留 `index.ts` 但在 JSDoc 写明"此为桶文件"。

## 4. 风险评估

### 4.1 风险矩阵

| 风险 | 概率 | 影响 | 等级 | 缓解 |
|------|------|------|------|------|

### 4.2 回滚策略

- **每个 Phase 结束后打 tag**：`git tag refactor-p1-done` / `refactor-p2-done` / ...
- **Phase 1–3 是 pure refactor（无行为变化）**：可以快速回滚
- **Phase 4 是行为敏感区**：
  - 4a–4c 是搬位置，行为不变
  - 4d（修 O-5）和 4e（抽 STRATEGIES 表）需保留 2 周观察期
  - 4f（Reporter 抽象）需保留 2 周观察期
- **Phase 5 是清理**：纯删除 + 文档，可一键 revert

### 4.3 不在本次重构范围（避免范围蔓延）

❌ **v2 设计**（brancher 重做、动态角色加载、异步多 run、跨 run 通信）
❌ **替换 UI**（TUI 改 CLI / JSON 模式）— 引入 `Reporter` 是为这个铺路，但实际替换不做
❌ **持久化 runs**（写到磁盘）— 当前是 in-memory，v1 不动
❌ **新增角色**（如 `test`、`docs`）— 属于功能扩展
❌ **替换 `pickAvailableModel` 为 LiteLLM / 多 provider 路由** — 属于基础设施升级
❌ **TypeScript 严格模式开启**（`strict: true`） — 单独项目
