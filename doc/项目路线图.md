## 借鉴 oira666/pi-subagent 的待办

### 0.4.1~0.4.3（小改/小配置）

- [ ] **depth / cycle guard** — `MAX_DEPTH` + 阻止同 agent 在链上重复出现。1 行配置，零成本。
- [ ] **planner 英文关键词正则** — 当前规则只能识别中文（`src/planner.ts:quickRuleBasedPlan`），加几条英文 fallback。

### 0.4.4~0.4.7（1~2 个文件改动）

- [ ] **递归 usage tree** — 给 `RunResult` 加 `usageTree: UsageTreeNode[]` 字段（照抄对方 schema）。
- [ ] **steering 广播** — 当前单 point 注入到 `pendingSupplements` Map，扩展为多 worker 广播。

### 0.5.0~0.5.5（多文件改动，建议单独写方案）

- [ ] **frontmatter 角色解析** — 让 `agents/*.md` 的 frontmatter 覆盖 `ROLE_DEFAULTS`，省一张表。`src/session/role-config.ts` 改造点。
- [ ] **check / adaptive 改 tool calling** — 当前凭正则匹配 "通过/pass/✓" 判断，改成 LLM tool calling 返回结构化判定。
- [ ] **persistence + resume** — 对方做在 `sessions-subagents/`，可以做在 `.dteam/sessions/`。涉及新增目录、序列化 `SessionManager`、resume 检测逻辑。**需要单独写方案**，因为它跨 `index.ts` / `orchestrator.ts` / `leaf.ts` 多个文件。

### 0.5.6+（结构性大改）

- [ ] **进程级隔离** — 把 `leaf.execute` 内部的 `createAgentSession` 换成 `spawn('pi', [...])`，子崩不影响主。涉及 `src/session.ts` 重写 + 信号通路（`SignalBus`）改造 + API key 透传策略调整。

## 待规划（未归到具体版本）

- 极端大任务处理：引入任务池 + 重试 + 超时（见 dteam 内部待办 P2）

## 更新原则

- 完成一项 → 把 `[ ]` 改成 `[x]`（借鉴部分），或在 dteam 内部待办表里删行
- 范围变更 → 调整"对应范围"列
- 重要新项 → 加到对应范围段
- 路线图变更尽量在独立 commit，方便回顾
