# dteam 术语表

dteam 是 Pi 里的 goal-driven（目标驱动）多 worker（工作者）协作扩展；简单任务由主 LLM 直接完成，需要群策群力时再进入 dteam 的前台编排循环。

本文件是 dteam 的命名权威：代码、文档、路线图和对外说明优先使用这里的术语。`_Avoid_` 表示容易造成误解或当前明确不采用的同义词。

## 1. 定位与边界

**dteam（召唤池 / 群策群力）**：
基于 goal（目标）自发生长的 Pi 扩展：为实现目标，Orchestrator（编排者）在同步循环里按需召唤专业角色（explore / design / build / check / close），任务从执行中涌现，不从预先穷举的 plan 派生。每个 worker 以进程内 `AgentSession`（代理会话）运行，使用最小资源加载器、工具白名单和 session 订阅来实现逻辑隔离；worker 的结果和信号实时回到 Orchestrator，由它决定下一步召唤谁。dteam 不是后台运行，不是流水线，不是预先穷举 plan 的执行引擎。
_Avoid_: 后台运行、background run、planner 穷举、solo/chain/team、流水线、预先 Task Plan、generic workflow platform、child pi process by default

**dteam vs dgoal（项目分工边界）**：
两个项目都是主 LLM 主导的同步循环，但本质模式不同，必须明确区分，不可混淆：
- **dgoal = 建检循环（build-check loop）**：主代理单兵持续推进，自己干，完成时由独立审核员（子进程零上下文终审）验证。
- **dteam = 群策群力**：主 LLM 协调，按需召唤多个专业角色协作；任务从执行中长出来，由信号驱动召唤决策。
主 LLM 自己判断：单代理能干用 dgoal，需要召唤专业角色用 dteam。两个项目独立并列，不合并。
_Avoid_: 把 dteam 和 dgoal 视为同一项目的两种模式、在两者间设置自动切换

**Main LLM / Main Agent（主模型 / 主代理）**：
直接和用户对话的主要执行者，也是决定是否调用 dteam 的入口。主 LLM 不应把所有任务都交给 dteam；只有复杂度来自拆解、交接、证据和验收时才调用。
_Avoid_: leader agent（如果暗示它要长期管理所有 worker）

**Orchestrator（编排者）**：
dteam 中围绕单个 goal（目标）持续读取 worker 信息、判断局面并决定下一步召唤谁的主体。这是 dteam 自己的正式术语，用来替代 ant-colony（蚁群系统）里的 `queen`（蚁后）隐喻。它强调的不是“队列派发”，而是根据信号持续调整走法的前台协作编排。
_Avoid_: Queen、queen、Coordinator、Dispatcher

**Orchestrator Loop（编排循环）**：
Orchestrator 为推进一个 goal 反复执行的同步前台循环：读取当前信息 → 判断下一步 → 召唤 worker → 通过 `session.subscribe` 接收结果与信号 → 继续或结束。它可以由用户显式 `/dteam` 启动，也可以由主 LLM 自动拉起 dteam 进入。
_Avoid_: background run、runId loop、ant queen loop

**Signal Store（信号存储）**：
dteam 在单个 goal（目标）的 Orchestrator Loop 内维护的临时信号空间，用来承接 worker 发出的 `progress / found / blocked / help` 等信号，并提供给 Orchestrator 判断下一步召唤谁。它是 ant-colony（蚁群系统）里 `pheromone`（信息素）概念在 dteam 中的去虫化版本；强调复用现有信号机制，而不是引入新的隐喻。Signal Store 默认随本次编排循环结束而清理，不落项目目录。

Signal Store 里的信号采用 TTL（time to live，存活时间）衰减：新信号优先影响 Orchestrator 决策，旧信号随时间失效，避免过期上下文继续干扰下一步召唤。
_Avoid_: pheromone、信息素、permanent memory、project database、append-only history

**Worker（工作者）**：
dteam 里承担某段协作职责的 agent（代理）实体。worker 是被 Orchestrator 按需召唤出来处理局部问题的专业角色。worker 运行在进程内 `AgentSession` 中，靠事件订阅把 progress / found / blocked / help 写入 `Signal Store`；worker 是 umbrella concept（总括概念），不在术语层预设更多固定子类，也不把计划文件命名为 `.worker.md` / `.worker.json`。
_Avoid_: plan file、chain file、Coordinator、child process default

**Fixed Role Pool（固定角色池）**：
dteam 的 worker 职责池固定为 `explore / design / build / check / close`。Orchestrator 只能在这五类角色中按需召唤，不开放项目级新增角色，也不把 dteam 做成 agent market（代理市场）或 role plugin（角色插件）系统。
_Avoid_: custom role market、project-defined role pool、dynamic role generation

**Completion Gate（收口闸门）**：
dteam 的 Orchestrator Loop 不自行判定完成；每个 goal 必须召唤 `check` 角色做收口确认才算完成。这防止 `check` 被忽略，保证群策群力有明确的收尾验证。它和 dgoal 的独立审核（零上下文子进程终审）在概念上呼应，但机制不同：dteam `check` 是进程内固定角色 worker，受 Logical Isolation（逻辑隔离）约束，不是独立 OS 子进程。
_Avoid_: Orchestrator self-termination、optional check、skip-close

**Adaptive Concurrency（自适应并发）**：
Orchestrator 可以同时召唤多个 worker，而不是严格串行。并发度会根据实际情况（如供应商 429 限流）自适应升降。这是 ant-colony `ConcurrencyConfig`（min/max/optimal/history/lastRateLimitAt）模式在 dteam 中的延续。
_Avoid_: strict sequential、fixed single worker、static batch size

**Multi-Provider Routing（多供应商路由）**：
为支撑自适应并发，dteam 的每个角色可以配置不同主模型和 fallback 链（多供应商），避免单供应商约 3 个并发就撞墙。这是 ant-colony `ModelOverrides` + `FallbackModels` + `resolveModelWithFallback` 模式在 dteam 中的延续。
_Avoid_: single provider、hardcoded model、no fallback

**LLM-Driven Orchestration（LLM 驱动编排）**：
Orchestrator 每一轮用一次 LLM 调用来判断下一步召唤谁，输入是 `goal + Signal Store 当前快照 + 已完成 worker 结果`，输出是“召唤哪个角色 / 给它什么任务 / 并发多少”。开放式决策只能靠 LLM；规则驱动会退化回预先穷举 plan，和自发生长的本质冲突。
_Avoid_: rule-driven dispatch、hardcoded workflow、static planner enum

**Logical Isolation（逻辑隔离）**：
dteam 放弃默认 OS 子进程隔离后，对进程内 worker 的 fresh（新鲜上下文）约束。每个 worker 使用 `SessionManager.inMemory()`、最小 `ResourceLoader`、工具白名单和独立 system prompt；只接收 Orchestrator 明确传入的 goal / task / Signal Store 摘要，不继承主对话完整上下文。
_Avoid_: shared main conversation context、implicit branch inheritance、full session reuse

**Opinionated Subagent Replacement（有立场的子代理替代层）**：
dteam 对通用 subagent（子代理）系统的替代定位：吸收有价值的能力形态，但用 507 的工作流约束过滤，不追求功能复刻。
_Avoid_: feature parity clone、generic subagent platform

**Configuration Surface（外部配置面）**：
用户或项目可以直接声明、覆盖或扩展 dteam 行为的入口，例如计划文件、角色配置或工作区策略。dteam 优先把能力沉淀为内部结构，只有真实痛点足够强时才扩大外部配置面。
_Avoid_: internal execution plan、runtime state

**对抗式合议（Adversarial Deliberation）**：
dteam 的定位（ADR 0006）：贯穿一个目标的全过程、带着共享上下文，逼出一个经多视角对抗检验的方案，并盯死执行不背叛方案的多角色协作。与 dgoal（建检循环：单兵带方案全程 + 独立审核审达标）零重叠——差异不在“带不带上下文”（两者主体都带方案全程），而在“方案是否经过对抗”与“审核能否看到方案承诺”。
_Avoid_: 自发生长、群策群力分工干活、多模型投票

**合议单元（Deliberation Unit）**：
一个需要对抗的决策点。一个目标可拆成多个合议单元，每个单元独立走多轮积分对抗。单元是 dteam 收敛的基本粒度。
_Avoid_: task、step、phase（这些是 dgoal 的术语，dteam 用合议单元）

**对抗回合（Adversarial Round）**：
合议单元内的一轮完整对抗，固定骨架：证据(explore) → 主张(N design 并行) → 反方(build/check 质疑) → 裁决(close 打分)。回合骨架由 runtime 确定化，不让 LLM 每轮重新拍板召唤谁。枚举有限变体，非无限自由组合。
_Avoid_: 自由召唤轮次、每轮 LLM 决策

**积分制（Score-based Convergence）**：
对抗回合的收敛机制，用 selection（选最好的方案）非 synthesis（融合成妥协方案）。每轮裁决打分：大幅胜出 +2 / 平局或微弱胜出各 +1 / 本轮未胜出 0；总分上限 5 分，至少 3 轮才允许收敛。先到 5 分者胜出，这是可复验的确定性收敛点。selection 非 synthesis 的依据：judge-based selection 在 42 任务全赢，synthesis 融合输给单模型 80%（arXiv 2603.20324 + 2502.00674）。
_Avoid_: synthesis 融合、多数投票、一次性 selection

**N design 差异化（Multi-Design Diversity）**：
对抗回合中 N 个 design 实例并行的防趋同配置，是积分制的物理基础。从两维度制造方案方差：模型维度（不同模型，呼应 Multi-Provider Routing）+ prompt 偏好维度（不同 system prompt 强调不同偏好，如稳健型/激进型）。两者都做，因为不是所有用户都持有多个模型——单模型用户靠 prompt 偏好维度也能制造差异。
_Avoid_: 同模型同 prompt 并行（无差异可选，退化成单方案）

**fresh 裁判（Fresh Adjudicator）**：
对抗回合中 close 角色承担 selection 打分时的中立性约束。close 强制用独立 AgentSession + fresh 上下文（借鉴 dgoal 的 fresh 子进程防自证机制），只见“各方案 + 反方质疑”，不见方案出处/历史，防偏好锚定。close 是 mini 版独立审核员，审“方案质量+漂移”而非 DoD 达标。
_Avoid_: close 带主会话上下文打分、close 生成期间可见方案历史

**summary 不转原文（Summary-only Feedback）**：
裁决反馈发给各 design 时只发摘要，不转对手方案原文。依据：发原文会让方案互相污染趋同，丢掉对抗产生的多样性信号（synthesis 陷阱）。发摘要 = 保留“知道对手好在哪”的反馈 + 维持各 worker 的 fresh 隔离。
_Avoid_: 转发原文、全量上下文广播

## 2. 运行模型

**Extension Runtime（扩展运行时）**：
Pi extension（扩展）承载工具、命令、UI、消息和会话条目的运行环境。dteam 的前台 Orchestrator Loop 依附在这个运行环境上，而不是依附于单次 tool call（工具调用）。
_Avoid_: tool wrapper、tool-only runtime

**In-process Execution（进程内执行）**：
dteam worker 的默认执行基底：用 Pi SDK（软件开发工具包）的 `createAgentSession` 创建进程内 `AgentSession`，通过 `session.subscribe` 实时读取 worker 事件并写入 Signal Store。它牺牲默认 OS 子进程隔离，换取实时信号、低启动开销和直接访问父进程内状态；隔离由 Logical Isolation（逻辑隔离）承担。
_Avoid_: process isolation by default、child pi process by default、spawn-first architecture

**Main-Agent Execution with Independent Audit（主代理执行 + 独立审核）**：
主 Agent 保持执行 owner（负责人），子代理只在关键边界提供独立验收或判断的协作模式。这是 [`pi-dgoal`](../../pi-dgoal) 的本质模式；dteam 借鉴其独立审核思想（`check` 收口），但不复制单兵执行形态。
_Avoid_: multi-worker execution、agent fanout

**No Default Resume（默认不恢复）**：
dteam 当前不做默认持久化 / resume（恢复）。Pi 进程退出后 active Orchestrator Loop 会丢失；召唤轨迹 / Signal Store 快照可写入 session entry（会话条目）用于回溯，不等于可恢复执行。见 [ADR 0004](./adr/0004-不做resume和默认持久化.md)。
_Avoid_: persistent Kanban、always-on job queue

## 2.5 已推翻（保留追溯）

以下概念在 0.6.0 被 [ADR 0005](./adr/0005-dteam-0.6.0-重定义为自发生长召唤池.md) 推翻，仅保留以追溯历史决策，**不再有效**：

- **后台运行 / `Run` / `runId` / `RunsStore` / `Background Collaboration State Machine`**：dteam 不再后台运行，改为同步前台 Orchestrator Loop。被 ADR 0005 推翻 ADR 0003。
- **`Task Plan` / `DPlan Contract` / `.dplan.*`**：不再预先穷举计划；召唤轨迹即计划。
- **`ExecutionPlan.mode`（`solo` / `chain` / `team`）/ `Mode`**：删除二维编排组织维度。
- **`Strategy`（`direct` / `build_check` / `adaptive`）/ `Two-dimensional Orchestration`**：删除二维编排执行维度。
- **`PlanStep` / `StepResult` / `RunResult.plan+steps`**：不再是编排核心结构；未来由 Orchestrator Loop 产出。
- **planner 穷举 / `quick path / Rule-based Plan` / `LLM JSON Fallback`**：改为 LLM-Driven Orchestration。
- **`SchedulingPlan` / `FileGraph` / `Preflight Scheduling` / `SchedulingBatch` / `SchedulingConflict` / `SchedulingDelay` / `Shared File` 主轴**：不再是编排核心；文件依赖可作未来辅助信号。
- **`Chain Inheritance`**：`chain` 模式已删，继承语义失效。
- **进程级 OS 子进程隔离作为默认**：改为进程内 `AgentSession` + Logical Isolation。

## 3. 角色与权限

**Role（角色）**：
dteam 写死的 worker 职责边界：`explore`、`design`、`build`、`check`、`close`。角色写死是当前安全和稳定性设计，不是临时缺陷。
_Avoid_: custom agent marketplace

**explore（探索者）**：
读代码、查资料、发现入口和风险。默认可读、可搜索，不改现有文件。
_Avoid_: implementation worker

**design（方案者）**：
输出实施方案、权衡和 ADR（架构决策记录）。默认可写新文件，但不 edit（编辑）现有文件。
_Avoid_: builder

**build（实现者）**：
执行计划、编写代码、改文档、补测试；当前唯一允许 `edit` 现有文件的角色。
_Avoid_: reviewer

**check（验收者）**：
跑测试、审查结果、指出问题。它验证行为和证据，不应直接修改已有代码。
_Avoid_: auto-fixer by default

**close（收口者）**：
总结、归档、沉淀经验。它负责把完成路径和残留风险讲清楚，不是必须每次都出现的固定阶段。
_Avoid_: mandatory release manager

**ROLE_DEFAULTS（角色默认配置）**：
运行时权威的角色工具、thinking（思考强度）和 description（描述）配置，位于 `src/session/role-config.ts`。当 `step.tools` 不存在或为空时回落到这里。
_Avoid_: agents/*.md frontmatter as runtime authority

**BASIC_TOOLS（基础工具集）**：
多数角色默认可用的基础工具：`read`、`bash`、`grep`、`find`、`ls`。
_Avoid_: all Pi tools

**DTEAM_TOOLS（dteam 通用工具集）**：
dteam 注入给 worker 的通用工具，目前包括 `worker_sendSignal` 和 `reference_architecture`。
_Avoid_: user-facing tool list

**availableTools（可用工具清单）**：
主 LLM 调用 dteam 时显式传入的当前可见工具名列表。planner LLM 只能从中选择 `step.tools`，dteam 会 intersect（取交集）过滤无效工具；不传则回落到 `ROLE_DEFAULTS`。
_Avoid_: dteam auto-discovery of tool universe

**Role Prompt（角色提示词）**：
`agents/*.md` 中的角色提示词文本。它影响 worker 行为，但工具权限和角色列表的运行时权威仍在代码里。
_Avoid_: role config source of truth

**frontmatter（前置元数据）**：
角色文件里的说明性元数据，当前主要作为未来兼容和文档提示，不是 dteam 的运行时配置权威。
_Avoid_: runtime override

## 4. 信号与协作回路

> 原第 5 节「调度与文件边界」（Scheduler / FileGraph / SchedulingPlan 等）已整体被 ADR 0005 推翻，移入 [§2.5 已推翻追溯](#25-已推翻保留追溯)。文件依赖可作 Orchestrator 的未来辅助信号，但不再是编排核心。

**Signal（信号）**：
worker 向上汇报的四类状态：`progress`（进展）、`found`（新发现）、`blocked`（受阻）、`help`（需补充信息）。在 dteam 里，信号写入 `Signal Store`（信号存储），供 Orchestrator 每轮 LLM 驱动决策使用。
_Avoid_: event、callback、log

**SignalPayload（信号载荷）**：
不同 signal type 对应的数据结构。`progress` 描述动作和影响；`found` 描述发现和严重性；`blocked` 描述错误类型和最后动作；`help` 描述缺什么、上下文、尝试和紧急度。
_Avoid_: arbitrary JSON

**worker_sendSignal（工作者发信号工具）**：
worker 向 Signal Store 发信号的机制。worker 不应自己伪造 workerId，由 Orchestrator 在召唤时注入。0.6.0 后写入由进程内 `session.subscribe` 承接。
_Avoid_: normal user-facing tool、伪造 workerId

**WorkerRun（工作者运行记录）**：
单个 worker 的生命周期快照，包含 id、role、task、input、output、signals、startedAt、finishedAt 和 status。未来按 Orchestrator Loop 的召唤轨迹维护，不再以 runId 为中心。
_Avoid_: PlanStep

**Help Self-heal（help 自愈）**：
worker 首次发 help 时，Orchestrator 召唤 `explore` 收集缺失信息，并把补充报告注入回原 worker。自愈失败或重复求助会进入升级流程。
_Avoid_: automatic retry loop

**Escalation to Human（升级到人类）**：
同一 worker 自愈后仍需要帮助时，dteam 通过 UI notify 通知用户，并等待用户补充信息注入。
_Avoid_: silent failure、infinite self-heal

**Peer Forwarding（同伴转发）**：
Adaptive Concurrency（自适应并发）下，Orchestrator 把一个 worker 的 `found` 或重要 `progress` 转发给同 goal 下其他正在跑的 worker，减少并发 worker 之间的信息孤岛。
_Avoid_: all-to-all chat


## 5. UI、报告与可观察性

**Reporter（报告器接口）**：
业务层向 UI 或其他展示层汇报 Orchestrator Loop、worker、signal、召唤轨迹的抽象接口。默认实现委托给 UIStore，未来可替换为 CLI / JSON / Web UI。
_Avoid_: direct uiStore calls from business logic

**UIStore（界面状态存储）**：
保存当前 Orchestrator Loop 的 UI 快照：goal、召唤轨迹、workers、signals、startedAt、finishedAt。对外返回 deep clone（深拷贝），避免 UI 层突变内部状态。
_Avoid_: source of execution truth

**UIWorkerState（界面工作者状态）**：
worker 在 UI 层的状态快照，包含 id、role、task、status、recentOutput、currentTool、files 和 signals。
_Avoid_: WorkerRun if lifecycle truth is required

**UISignal（界面信号）**：
signal 的 UI 摘要形态，只保留 type、workerId、summary、timestamp。
_Avoid_: full SignalPayload

**/dteam Panel（/dteam 面板）**：
用户查看运行态的主界面，可折叠 / 展开，展示 Orchestrator Loop 推进、Signal Store 快照、当前召唤的 worker 等。
_Avoid_: separate TUI app

**Widget（小组件）**：
Pi editor（输入框）上方的紧凑运行态展示。dteam widget 只显示低噪声摘要（Orchestrator Loop 进度 + 召唤轨迹），避免把 worker 长输出堆进主对话。
_Avoid_: full log viewer

**Live Loop View（实时循环视图）**：
0.6.0 取代旧「Live Plan」的概念：在 Pi editor 上方低噪声展示 Orchestrator Loop 的事中推进（当前召唤的 worker、Signal Store 关键信号、是否进入 check 收口），不是预先计划的展示。

用户对一次 dteam 的感知粒度是三段：**开启 dteam → 完成工作 → 验收工作（check 收口）**。worker 内部的工具调用轮次、逐轮推理细节属于黑箱，不进 UI；低噪声的根本理由就是这个感知粒度，而非单纯的视觉整洁。
_Avoid_: 预先 Task Plan 浮层、verbose worker log as primary view、worker 工具轮次展示

**Evidence（证据）**：
dteam 用来支撑“完成”的可回溯材料，包括召唤轨迹、worker 结果、Signal Store 快照、validation result、`check` 收口结论。
_Avoid_: worker says done

**DoD / Definition of Done（完成定义）**：
dteam 的轻量完成协议：0.6.0 后由 Completion Gate（强制 `check` 收口）定义；不引入复杂审批流。
_Avoid_: approval workflow、enterprise gate

## 6. API 与入口

**dteam tool（dteam 工具）**：
对外唯一工具，主 LLM 用它拉起 Orchestrator Loop（启动方式 C 混合）。保持单工具哲学，不拆成多个用户可见工具。
_Avoid_: dteam_status / dteam_plan / dteam_worker multiple tools

**/dteam command（/dteam 命令）**：
用户显式启动 Orchestrator Loop 的 slash command（斜杠命令）：`/dteam <goal>`。也可用于切换面板。
_Avoid_: background launch returning runId

**Sync Foreground Execution（同步前台执行）**：
dteam 启动后进入同步前台 Orchestrator Loop，阻塞主对话直到 `check` 收口完成；不再返回 `runId`、不再后台运行。
_Avoid_: background run、runId、立即返回 running

**status channel（状态通道）**：
dteam 运行态通过 `/dteam` 面板、widget、status bar（状态栏）、notify（通知）展示。同步前台执行下，进度随循环推进实时可见。
_Avoid_: long-running onUpdate stream、后台轮询

**reference_architecture（架构参考工具）**：
dteam 提供给 worker 的内部参考工具，用于查询架构模式资料。它是 worker 辅助工具，不是用户主要入口。
_Avoid_: external docs search

## 7. 内部模块

**orchestrator（编排器）**：
`src/orchestrator.ts`，dteam Orchestrator Loop 主循环：读 Signal Store → LLM 驱动决策 → 召唤 worker → 收结果/信号 → 写 Signal Store → 继续 / 进入 check 收口。0.6.0 重写方向。
_Avoid_: planner、旧 Plan→FileGraph→SchedulingPlan→Execute 流水线

**leaf（叶子执行层）**：
`src/leaf.ts` 和 `src/leaf/*`，负责召唤单个 worker（进程内 `AgentSession`）执行任务，并处理 help 自愈、输出提取和 worker lifecycle。
_Avoid_: branch agent

**session（会话层）**：
`src/session.ts` 和 `src/session/*`，负责创建进程内 worker `AgentSession`、加载角色 prompt、解析模型（含 Multi-Provider Routing）、注入工具和资源、实现 Logical Isolation。
_Avoid_: user conversation session

**signals module（信号模块）**：
`src/signals/*`，0.6.0 后负责 Signal Store（信号存储，TTL 衰减）的实现与导出，供 Orchestrator 读取决策。
_Avoid_: UI event system、RunsStore

**ui module（界面模块）**：
`src/ui/*`，负责 UIStore、widget 渲染、面板命令和显示辅助函数。
_Avoid_: business logic owner

**scheduler module（调度模块，将降级）**：
`src/scheduler/*` 原负责 file graph / preflight scheduling。0.6.0 后不再是编排核心；文件依赖可降级为 Orchestrator 决策的辅助信号。
_Avoid_: 编排核心

**Legacy Task / Decision（兼容旧类型）**：
`src/tools.ts` 仍保留的旧递归分解类型与 `ExecutionPlan` / `PlanStep` / `SchedulingPlan` 结构，当前主要为兼容历史接口。0.6.0 重写时会逐步退场，新增设计不应围绕它们扩展。
_Avoid_: current 编排 schema

## 8. 外部参考与明确不做

**SwarmFlow Principle（SwarmFlow 原则）**：
借“编排和智能分离”：确定关系由 runtime 执行，具体理解和生成交给 worker LLM。不照搬 `workflow.py` 或通用 workflow 平台。
_Avoid_: visual workflow editor

**MiMo Code Pattern（MiMo Code 模式）**：
借“结构化编排”和旁路角色启发。Goal verifier / writer worker 是远期候选，不进入默认固定流水线。
_Avoid_: Max Mode、Dream、Distill by default

**Routa Task Protocol（Routa 任务协议）**：
借“完成要有证据、门禁和交接”思想，不搬持久 Kanban、审批流或企业级 Harness 平台。
_Avoid_: persistent Kanban

**pi-subagents Reference（pi-subagents 参考）**：
借自然语言入口、background runs、async widget、grouped result、child safety。当前不借 agent / chain 文件体系，不开放角色市场。
_Avoid_: feature parity with pi-subagents

**rpiv-todo UI Reference（rpiv-todo UI 参考）**：
借 live overlay（实时浮层）、done 删除线弱化、低噪声折叠思路。0.6.0 后用于 Live Loop View 的事中展示（非预先计划浮层）。branch replay 与 ADR 0004（不做 resume）冲突，仅作为远期候选。
_Avoid_: todo manager inside dteam、预先 Task Plan 浮层

**Worktree / File Lock / Auto Merge（工作区 / 文件锁 / 自动合并）**：
当前明确不做。只有当并发 worker 的并行写隔离成为真实痛点时，再评估 worktree。
_Avoid_: default parallel write isolation

**Custom Role System（自定义角色系统）**：
当前不做。5 个写死角色覆盖 507 的个人编程工作流，工具权限也更容易验证。见 ADR 0002。
_Avoid_: role marketplace、agent discovery

## 9. 已解决（原“待确认”）

以下条目原列“待 507 确认”，在 0.6.0 重定义中已由 18 条决策解决：

- **Done Evidence（完成证据）**：由 Completion Gate（强制 `check` 收口）承担；不再需要单独字段。
- **Goal Verifier（目标验收者）**：即固定角色 `check`；不引入独立 verifier，避免与 dgoal 独立审核混淆。
- **Branch Replay（分支重放）**：受 ADR 0004（不做 resume）约束；远期如借用，仅用于重建展示态，不恢复执行态。
