# doc 文档导航

> 本目录按文档职责拆分：架构与运行、能力参考、路线图、版本实施方案、历史归档。后续写文档前，先确认它属于哪一类，避免把架构现状、路线图和具体落地方案混在一起。

## 阅读顺序

接手 dteam 或做架构/代码决策前，建议按这个顺序读：

1. `10-架构与运行/10-系统架构.md` — 二维编排模型 + 三阶段流水线
2. `10-架构与运行/11-角色系统.md` — 5 个角色的工具权限与职责
3. `10-架构与运行/12-API参考.md` — 工具 + 命令 + 内部 API
4. `10-架构与运行/13-设计-v2与实施现状.md` — 原始设计 vs 实际代码的 gap 分析
5. `30-路线图/30-项目路线图.md` — 唯一权威路线图（当前版本 0.4.0）
6. `40-版本实施方案/40-Agent-Teams借鉴实施方案.md` — 并行治理落地方案
7. `40-版本实施方案/41-工具动态加载方案.md` — 工具列表传递机制
8. `../src/README.md` — 代码组织（必读）

需要了解外部生态时：

9. `20-能力参考/20-Pi版本兼容性与影响分析.md` — 上游 Pi 更新影响评估
10. `20-能力参考/22-与pi-subagent对比.md` — 最相关的竞品对比

## 目录职责

| 目录 | 职责 | 是否权威 |
|---|---|---|
| `10-架构与运行/` | 当前架构、角色系统、API 接口、设计与实施 gap | 是，当前实现权威 |
| `20-能力参考/` | 上游 Pi 兼容性、扩展 API 清单、竞品/友商对比分析 | 是，作为事实参考 |
| `30-路线图/` | 演进计划（按 npm semver 时间窗口分组）、远期架构扩展 | 是，路线图唯一权威 |
| `40-版本实施方案/` | 版本级功能或专项工程的落地方案 | 规划 / 执行中，受路线图约束 |
| `90-归档/` | 已完成或过时的历史方案、早期设计稿 | 否，仅作历史参考 |

## 文档类型约定

### 架构运行文档

回答：
- 当前代码分层是什么？二维编排模型怎么工作？
- 5 个角色分别能做什么工具？权限边界在哪？
- 对外 API 是什么？内部 API 怎么调？
- 设计稿和实际代码差在哪？

不写：
- 哪个版本做什么功能（归 `30-路线图/`）
- 竞品分析（归 `20-能力参考/`）

### 能力参考文档

回答：
- 上游 Pi 更新了什么？对我们有什么影响？
- Pi 扩展 API 有哪些表面？
- 竞品/友商做了什么？我们能借什么？

不决定：
- 哪个版本要做哪些借鉴（归 `30-路线图/`）
- 具体实施细节（归 `40-版本实施方案/`）

### 路线图文档

回答：
- 当前版本还剩什么？
- 下一个 minor / patch 做什么？
- 远期架构扩展方向？

不承载：
- 大段代码设计
- 详细字段契约（归 `40-版本实施方案/`）

### 版本实施方案文档

回答：
- 某个功能为什么做？
- 输入 / 输出 / 数据契约是什么？
- 具体改哪些文件？依赖什么前置条件？
- 不做什么，边界在哪里？

必须受 `30-路线图/30-项目路线图.md` 约束。

### 归档文档

只用于查历史事实。若与当前路线图或架构文档冲突，以 `30-路线图/` 和 `10-架构与运行/` 为准。
