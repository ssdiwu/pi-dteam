# doc 文档导航

> 本目录记录 dteam 的当前定义、外部参考、路线图和版本实施方案。
>
> 当前主线：**dteam = 模型分级路由执行层 + 主代理证据驱动多轮路由协议 + 会话级后台运行时**。主代理负责定义证据问题、分轮派发、综合、升级与验收；Worker Manager 只负责已派发 worker 的生命周期、signal 和统一报告。模型工具为 `dteam_dispatch`、`dteam_respond`、`dteam_recover`、`dteam_wait`，内部角色仍是 T1/T2/T3 三档。
>
> 与 [`pi-dgoal`](../../pi-dgoal) 独立并列：**dteam = 多模型分级路由，dgoal = 单模型建检循环**。主 LLM 自己判断用哪个，不合并，不自动切换。
>
> **实施状态**：0.7 T1/T2/T3 fresh dispatch 基础已完成；0.8 Worker Manager、四工具、有类型 signal、受限动态工具、`/dteam` 管理与取消已完成；ADR 0020 主代理协议和 ADR 0021 统一 WorkerReport 已落地。

## 当前文档原则（0008 重定位后）

1. **定位先行**：dteam 不是通用工作流平台，不是召唤池，不是对抗式合议；它是模型分级路由执行层 + 主代理证据驱动协议——低档 worker 分轮取得证据和完成机械活，强模型专注问题定义、综合、路由与验收。
2. **四工具 dteam**：`dteam_dispatch`、`dteam_respond`、`dteam_recover`、`dteam_wait` 分别承担派发、普通回应、超时恢复与显式依赖等待；主模型提交已就绪 worker，Worker Manager 负责后台执行和 signal，主模型仍负责依赖与后续路由。
3. **进程内 worker**：worker 是进程内 `AgentSession`（代理会话）+ Logical Isolation（逻辑隔离），不默认 spawn（启动）OS 子进程。dispatch 创建的 worker 都是 fresh session。
4. **T1/T2/T3 取代五角色**：内部角色 = 模型档位（T1 思考 / T2 标准 / T3 快速），不再有 explore/design/build/check/close 职能分工。标准锚定供应商产品线层级。
5. **思考跟随档位**：T1 高思考 / T2 中 / T3 低，不独立成维；难任务走回退换强模型（自带高思考），不是让小模型多想。
6. **fresh 验收对抗主模型倾向**：主模型既是分配者又验收会放水；dispatch 的 fresh 特性保证验收 worker 不看主会话/方案出处（复活 0007 的 fresh check 零件）。
7. **dteam vs dgoal 边界**：dteam = 多模型分级路由（小任务小模型并行 + 回退 + 验收），dgoal = 单模型建检（全程一个强模型 + 独立审核审 DoD）；独立并列。
8. **外部参考只借轻动作**：外部参考源（ant-colony / zcode-swarm / pi-subagents 等）彼此平级，不高于 dteam 自身优先级；借多态分工、派发形态、fresh 审核、可观测；不照搬自组织涌现、竞争认领、液态拓扑、重型编排。
9. **0.8 只升级运行形态**：会话级后台 worker + 有类型星型 signal 只服务于已派发的单任务协作；不把 Worker Manager 变回 Orchestrator Loop，也不把 Signal Log 变回 TTL Signal Store。见 `10-架构与运行/15-…` 与 ADR 0009。
10. **报告诚实分层**：Manager completed、任务 outcome、实际 activities 与 verification depth/status 分开；人工复测留在 worker 报告之外。
11. **外部地图在 dteam 之外**：issue / PRD / spec / dgoal plan 保存耐久目标与依赖，dteam 只消费当前切片，不建立 resume 或 ID 映射。
12. **路线图四档**：要做 / 不做 / 已推翻 / 远期；已推翻项保留追溯链（指向推翻它的 ADR）。
