# doc 文档导航

> 本目录记录 dteam 的当前定义、外部参考、路线图和版本实施方案。
>
> 当前主线：**dteam = 模型分级路由执行层**。主模型（T1 思考档）负责思考/路由/验收，小任务 fan-out 给小模型（T3 快速档）批量并行做，思考跟随档位，搞不定走 fresh 验收 → 回退强模型。单工具 `dteam_dispatch` 统一执行/验收/回退；内部角色 = T1/T2/T3 三档（取代五角色）。
>
> 与 [`pi-dgoal`](../../pi-dgoal) 独立并列：**dteam = 多模型分级路由，dgoal = 单模型建检循环**。主 LLM 自己判断用哪个，不合并，不自动切换。
>
> **实施状态**：0.7 T1/T2/T3 fresh dispatch、档位路由、provider/T1 回退、并发与唯一公开 `dteam_dispatch` 已完成并有自动化测试；0.6 runtime 与 UI 已删除。

## 当前文档原则（0008 重定位后）

1. **定位先行**：dteam 不是通用工作流平台，不是召唤池，不是对抗式合议；它是模型分级路由执行层——小任务甩给小模型批量做，强模型专注思考/路由/验收。
2. **单工具 dispatch**：dteam 暴露唯一工具 `dteam_dispatch(task, tier, thinking?, tools?)`；执行/验收/回退都是它的不同用法；主模型并发调用多个 dispatch = 并行 fan-out。
3. **进程内 worker**：worker 是进程内 `AgentSession`（代理会话）+ Logical Isolation（逻辑隔离），不默认 spawn（启动）OS 子进程。dispatch 创建的 worker 都是 fresh session。
4. **T1/T2/T3 取代五角色**：内部角色 = 模型档位（T1 思考 / T2 标准 / T3 快速），不再有 explore/design/build/check/close 职能分工。标准锚定供应商产品线层级。
5. **思考跟随档位**：T1 高思考 / T2 中 / T3 低，不独立成维；难任务走回退换强模型（自带高思考），不是让小模型多想。
6. **fresh 验收对抗主模型倾向**：主模型既是分配者又验收会放水；dispatch 的 fresh 特性保证验收 worker 不看主会话/方案出处（复活 0007 的 fresh check 零件）。
7. **dteam vs dgoal 边界**：dteam = 多模型分级路由（小任务小模型并行 + 回退 + 验收），dgoal = 单模型建检（全程一个强模型 + 独立审核审 DoD）；独立并列。
8. **外部参考只借轻动作**：外部参考源（ant-colony / zcode-swarm / pi-subagents 等）彼此平级，不高于 dteam 自身优先级；借多态分工、派发形态、fresh 审核、可观测；不照搬自组织涌现、竞争认领、液态拓扑、重型编排。
9. **路线图四档**：要做 / 不做 / 已推翻 / 远期；已推翻项保留追溯链（指向推翻它的 ADR）。
