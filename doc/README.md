# doc 文档导航

> 本目录记录 dteam 的当前定义、外部参考、路线图和版本实施方案。
>
> 当前主线：**dteam = 基于 goal（目标）自发生长的多 worker 群策群力扩展**。主 LLM 协调，按需召唤固定五角色（explore / design / build / check / close）协作；同步前台 Orchestrator Loop（编排循环）；强制 `check` 收口。
>
> 与 [`pi-dgoal`](../../pi-dgoal) 独立并列：**dteam = 群策群力（召唤池），dgoal = 建检循环（单兵 + 独立审核）**。主 LLM 自己判断用哪个，不合并，不自动切换。

## 当前文档原则（0.6.0 重定义后）

1. **定位先行**：dteam 不是通用工作流平台，不是固定流水线，不是预先穷举 plan 的执行引擎；它是基于 goal 自发生长的召唤池。
2. **同步前台运行**：dteam 进入同步前台 Orchestrator Loop，阻塞主对话直到 `check` 收口；**不再后台运行、不再返回 `runId`**。
3. **进程内 worker**：worker 是进程内 `AgentSession`（代理会话）+ Logical Isolation（逻辑隔离），不默认 spawn（启动）OS 子进程。
4. **固定五角色是有意设计**：`explore / design / build / check / close`，不做角色市场；`check` 是强制收口闸门。
5. **LLM 驱动 + 信号驱动**：Orchestrator 每轮一次 LLM 调用决定召唤谁，依据 Signal Store（信号存储，TTL 衰减）。
6. **dteam vs dgoal 边界**：群策群力用 dteam，单兵推进 + 独立审核用 dgoal；独立并列。
7. **外部参考只借轻动作**：外部参考源（ant-colony / pi-subagents / swarm-ide 等）彼此平级，不高于 dteam 自身优先级；判断借不借的主语永远是 dteam 的真实痛点，不是参考源的功能清单。借实时信号、可观测、状态边界、自然语言可用性；不照搬固定流水线、重型持久化、进程树或完整多 agent 平台。
8. **路线图四档**：要做 / 不做 / 已推翻 / 远期；已推翻项保留追溯链（指向推翻它的 ADR）。
