# 工具动态加载方案

> **版本归属**：0.4.1 候选（0.4.0 = 当前发布版）
> **状态**：**已实现，未启用为 0.4.0 默认**——0.4.0 行为零变化，0.4.1 启用后 LLM 路径会按运行时已加载工具动态选 tool 子集
> 讨论时间：2026-06-06
> 与 `扩展API参考.md` 配套：那份是 Pi 扩展 API 参考表，这份是 C 的设计稿。

## 问题

`src/session/role-config.ts` 第 24 行：

```ts
explore: {
  tools: [...BASIC_TOOLS, "tinyfish_search", "tinyfish_fetch", ...DTEAM_TOOLS],
  //                                       ^^^^^^^^^^^^^^^^^^^^^^^^^
  //                                       硬编码：依赖 tinyfish 这个具体扩展
},
```

**blast radius**：
- 用户没装 tinyfish → LLM 拿到不存在的工具名 → explore 角色废
- 用户装了别的 search 扩展（`pi-web-access` / `pi-finder-subagent` / ...）→ dteam 不识别
- role prompt (`agents/explore.md`) 说"联网搜索"是抽象的，tool 列表写 `tinyfish_search` 是具名的——**两层错位就是 bug 根源**

## 方案选择

| 方案 | 思路 | 评估 |
|------|------|------|
| A. fallback chain | role 写多个候选工具名按序尝试 | ❌ 候选名要人维护 → 面对未来工具不够用 |
| B. capability map | role 声明"需要什么能力"，再映射 | ❌ 多一层抽象 → 0.4.0 故意少抽象 |
| **C. runtime probe + LLM-as-selector** | 运行时枚举已加载工具，planner LLM 据此为每个 step 选 tool 子集 | ✅ 不写白名单、交给 LLM 决定 |

**507 的原话**（决策依据）：
> "你看到了有对应的探索工具，那么在派出这个探索的时候，你就会告诉他说可以用哪些工具"

**翻译**：orchestrator / planner 看到 Pi 当前加载了哪些工具 → 决策 → 派 worker 时把"可用工具"告诉它。

## 数据流

```
planner.plan(goal, ctx)
  │
  ├─ quickRuleBasedPlan(goal)
  │     → ExecutionPlan { steps: [{ role, task, strategy, tools: undefined }] }
  │     → 走老路径：createWorkerSession 降级用 ROLE_DEFAULTS[role].tools
  │
  └─ LLM plan (复杂 goal)
        → listAvailableTools(cwd) 枚举 Pi 已加载工具
        → systemPrompt 里塞入 "可用工具清单"（含 name + description）
        → LLM 返回 JSON: { steps: [{ role, task, strategy, tools: ["tinyfish_search", ...] }] }
        → 解析时 intersect(loadedTools, step.tools) 过滤掉不存在的工具
        → createWorkerSession 用 step.tools 建 session
```

## 关键约束

- **0.4.0 的"JSON 模式而非 tool calling" 不变**——planner 还是纯文本 prompt + JSON 解析；可用工具以**文本**塞入 systemPrompt，不动 LLM 工具调用
- **`tools?: string[]` 是可选的**——planner 不写也能跑（降级到 role defaults），0.4.0 → 0.4.1 平滑过渡
- **不动 agents/*.md**——role 描述保持抽象，工具名由 orchestrator 注入
- **不动 ROLE_DEFAULTS**——保持作为 0.4.0 行为的 fallback；不引入 capability map 等新抽象
- **LLM 填错的工具名会被 intersect 过滤掉**——planner 拿到 LLM 返回的 `step.tools` 后，与运行时已加载工具集合求交，缺失的丢弃，保留有的；全空就降级到 ROLE_DEFAULTS

## 验证场景

| 场景 | 期望行为 |
|------|----------|
| 用户装了 tinyfish | 行为零变化（0.4.0 路径走 ROLE_DEFAULTS；LLM 路径工具列表包含 tinyfish） |
| 用户没装 tinyfish、装了 pi-web-access | planner LLM 看到 "web_search" 工具，把它填进 explore step.tools |
| 用户什么都没装 | planner LLM 只看到 5 个 pi 内置 + 0 个扩展，explore 降级到 read+bash+grep |
| LLM 拼错工具名 | planner intersect 后过滤掉；不传给 createAgentSession |
| 规则命中（quick path） | tools 字段 undefined，走老路径；不引入 LLM 成本 |
