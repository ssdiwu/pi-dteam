# 经验笔记

> 记录可调整的做法与避坑经验；每条使用“现象 + 做法 + 证据”，不替代术语表或决策档案。

## 对外直接说“新建会话 / 新建 worker”

**现象**：把项目既有的 `fresh session` / `fresh worker` 对外译成“全新工作代理”，容易让人误以为引入了新一代 worker，掩盖实际变更只是某个初始化环节。

**做法**：面向用户直接说“新建会话”或“新建 worker”。只有引用项目正式定义时才保留 `fresh session`；首次出现可解释为“新建且不继承主会话上下文”。不要另造“全新工作代理”等中文术语。

**证据**：`doc/术语表.md` 已用 Fresh 验收（Fresh Review）与 Logical Isolation（逻辑隔离）定义“不继承主会话”的边界；`v0.9.3` 没有改变 worker 生命周期，只修复了新建 worker 会话中所选自定义 provider runtime（供应商运行时）的传播。发布后的解释中使用“全新工作代理”造成了“新旧 worker 有何差异”的误解。
