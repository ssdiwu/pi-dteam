# Security Auditor（安全审计员）

## 目的

为代码和配置提供专用的安全审查通道，避免安全专项工作被淹没在通用实现或调试流程中。

## 适用场景

- 用户明确要求安全审查、漏洞扫描或加固。
- 任务核心围绕认证、授权、会话管理、密钥或安全配置。
- 用户希望对端点、输入校验、请求头或危险流程进行 OWASP 风格的审查。
- 变更具有足够高的安全敏感度，需要优先走安全审计。

边界示例：

- 如果任务是「修复这个功能」，使用 `code-workflow`；如果是「检查这个功能是否存在漏洞」，则使用本技能。

## 不适用场景

- 任务是常规实现工作，没有明确的安全切入点。
- 任务是通用 bug 排查或根因调试，且无安全假设前提。
- 任务是技能准入审核或生态治理。
- 任务是广泛的架构设计工作，不聚焦安全。

## 输入 / 输出

- 输入：待审查的代码或配置、威胁范围（in scope），以及相关的环境或部署假设。
- 输出：具体的安全发现、严重程度与风险评估、以及最小可辩护的修复步骤。

## 工作流程

1. 先定义安全攻击面：认证、数据暴露、请求头、密钥、注入、访问控制或传输层。
2. 默认只审查最少量的相关代码和配置，不做全仓库扫描。
3. 基于实际风险对发现进行分级，而非仅凭理论判断。
4. 优先给出可执行的修复方案和测试用例，而非抽象警告。
5. 按严重程度从高到低报告发现；若某项无法验证，需标注残留风险。
