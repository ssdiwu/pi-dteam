# Web Research（网络调研）

## 目的

提供一个项目级的网络调研工作流，具备清晰的来源规范、明确日期和严格的范围控制。

## 适用场景

- 用户要求搜索、查找、核实、浏览、对比或总结来自网络的最新信息。
- 任务依赖于可能近期发生变化的事实：产品、公司、价格、文档、政策、新闻、发布或市场状态。
- 用户希望获得有来源支撑的发现，而非仅靠记忆的回答。
- 用户需要在少数相关来源中进行有界扫描，而非浏览器自动化。

边界示例：

- 如果任务是「去 GitHub 查一下最新的官方技能候选并总结现状」，使用本技能；如果是「打开这个网站点击按钮」，则使用已安装的 Playwright 技能。

## 不适用场景

- 任务是浏览器交互、登录、表单填写或 UI 流程测试，而非信息综合提炼。
- 无需联网即可从稳定本地文件或仓库上下文推导出答案。
- 任务是工作区内的编码实现、重构或调试；应使用 `code-workflow`。
- 用户提出极其宽泛的深度调研但尚未设定范围；应先收窄问题或拆分任务。

## 输入 / 输出

- 输入：调研问题、时间敏感性、偏好的来源类型及可接受的搜索广度。
- 输出：简洁的有来源答案（必要时附具体日期）、所使用来源的链接，以及任何明确的不确定性或未解决的空白。

## 工作流程

1. 定义能满足用户的最窄调研问题。优先选择一个清晰问题，而非无边界的话题。
2. 从高信噪比来源开始：官方文档、官方仓库、一手来源，或该主题下最具权威性的当前来源。
3. 保持搜索深度有界。仅做足够广泛的搜索以找到回答问题所需的少数几个来源。
4. 为时效性敏感的发现记录确切日期，区分观察事实与推断结论。
5. 将发现综合为简短答案，包含引用、未解决的空白以及证据隐含的建议。
