# 网络调研规则

## 来源优先级

按以下顺序偏好来源：

1. 官方文档、官方仓库、官方公司或产品页面
2. 一手公告、标准机构或原始数据集
3. 仅在一手来源缺失或不足时才使用信誉良好的二手报道

如果一手来源唾手可得，不要从低信噪比的摘要开始。

## 有界搜索

默认采用小型搜索循环：

1. 用聚焦关键词搜索一次
2. 打开最强的 1～3 个来源
3. 若证据已充分则直接回答
4. 仅在存在明显缺口或矛盾时才再次搜索

除非用户明确要求更大的报告，否则避免陷入深度调研蔓延。

## 时效性敏感的事实

对任何可能变化的信息，都附上具体日期：

- 发布日期
- 出版日期
- 价格、政策、负责人、可用性或排名的「截至」日期

如果用户使用相对时间如「今天」或「最新」，在答案中有用时将其转换为明确日期。

## 输出格式

保持答案简洁且由证据驱动：

- 先给直接答案
- 再列关键支撑发现
- 然后附来源链接
- 最后说明任何未解决的不确定性

## 边界规则

### 对比已安装的 Playwright 技能

当主要工作是与实时网站 UI **交互**时，使用 Playwright。

当主要工作是从网络来源**提取、验证和综合信息**时，使用 `web-research`。

### 对比 `code-workflow`

当产出物是仓库中的**代码**时，使用 `code-workflow`。

当产出物是有来源的**答案或证据摘要**时，使用 `web-research`。

## 正面示例

- "去 GitHub 查一下现在有哪些官方技能。"
- "帮我核实这个产品现在还支不支持某功能，并给来源。"
- "比较两三个方案的当前状态，别靠记忆回答。"

## 反面示例

- "打开这个网站点注册按钮。"
- "把这个 bug 修掉。"
- "总结我刚贴给你的这段文本。"
