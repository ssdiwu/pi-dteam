# Architecture Designer（架构设计师）

## 目的

为结构性技术决策提供专用通道，将架构工作与实现细节分离。

## 适用场景

- 用户询问系统设计、服务边界、架构权衡或技术方向。
- 存在多种实现方案，且选择会显著影响可维护性或扩展规模。
- 任务需要 ADR 风格的推荐意见或架构评审。
- 产出物是设计决策，而非代码。

边界示例：

- 如果用户说「帮我实现这个功能」，使用 `code-workflow`；如果说「这个系统应该怎么设计」，则使用本技能。

## 不适用场景

- 任务是明确的实现工作，不存在重大设计歧义。
- 任务是视觉 UI/UX 设计。
- 任务是调试或测试具体故障。
- 用户只需要快速的事实查询。

## 输入 / 输出

- 输入：需求、约束条件、规模假设、现有架构以及待决策的问题。
- 输出：推荐的架构方向、关键权衡、被否决的备选方案及主要风险。

## 工作流程

1. 明确具体的设计问题和关键约束条件。
2. 仅对比少数可行方案，不做穷举式探索。
3. 显式列出权衡维度：复杂度、可运维性、扩展规模、成本和故障模式。
4. 务实优先，避免为假设性需求过度设计。
5. 返回清晰的推荐方案，包含理由和下一步实施建议。
