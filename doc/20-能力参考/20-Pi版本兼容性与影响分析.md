## 影响评估：🟡 可改进 — project_trust 自动信任提升多代理体验

### 变更详情

新增 `project_trust` 扩展事件：

```typescript
pi.on("project_trust", async (event, ctx) => {
  // event.cwd - 当前工作目录
  // ctx: { cwd, mode, hasUI, select, confirm, input, notify }
  if (await ctx.ui.confirm("Trust project?", event.cwd)) {
    return { trusted: "yes", remember: true };
  }
  return { trusted: "undecided" };
});
```

- 仅 **user/global 和 CLI `-e` 扩展** 参与（project-local 扩展在 trust 之后才加载）
- 返回 `"yes"` / `"no"` 则拥有决定权（首个 yes/no 获胜，抑制内置提示）
- `remember: true` 可持久化决定

### 与 dteam 的关系

dteam 是**模型分级 dispatch 执行层**：worker 在调用者 `cwd` 内创建 fresh session，默认 Logical Isolation 不继承扩展；不跨项目切换 cwd、不维护 resume 或 runId。

| 场景 | 与 project_trust 的交互 |
|------|------------------------|
| 当前项目已由 Pi 主会话加载 | dispatch worker 复用该 cwd，不额外改变 trust 决策 |
| 并行 worker | 仅在同一 cwd 创建独立内存 session，不产生跨项目 trust 弹窗 |
| 用户切换到新项目 | 由 Pi 主会话的内置 trust 流程处理，dteam 不拦截 |

### 影响

当前无直接功能缺口。自动信任会扩大安全边界，且 dteam 没有跨项目编排需求，因此保持不监听 `project_trust`。若未来出现明确的跨 cwd dispatch 需求，需先单独 ADR 决策，不能默认放行。

### 示例代码（方案 B — 委托 + 记忆）

```ts
// 在 extension 入口注册
pi.on("project_trust", async (event, ctx) => {
  // dteam 子任务通常访问用户自己的项目，默认倾向信任
  // 但仍给用户一次确认机会，之后记住决定
  if (!ctx.hasUI) return { trusted: "undecided" };

  const confirmed = await ctx.ui.confirm(
    "dteam: 信任此项目目录？",
    `子代理将访问: ${event.cwd}`
  );
  return { trusted: confirmed ? "yes" : "no", remember: confirmed };
});
```

### 优先级

⚪ **当前不做** — 0.7 dispatch 不跨 cwd；只有出现真实跨项目派发需求时才单独评估。

## 次要关联

### Cache-hit Visibility（CH）

- Footer 新增缓存命中率显示。
- dteam 的并行 dispatch 调用 LLM，CH 指标有助于调优 prompt 设计和 token 使用效率。
- **无需代码改动**；dteam 没有 `reporter.ts`。

### Compaction Prompt 措辞（#5401）

- dteam 的子代理属于 **non-coding agent** 场景。
- 当 dteam 会话触发 compaction 时，Pi 内部现在会用中性 AI 助手措辞（不再偏 coding）。
- **正面影响**：dteam 的压缩摘要质量应该会有微升。
- **无需代码改动**。

### Skill Prompt 间距（#5371）

- dteam 不以 skill 形式分发，**无影响**。
