# Pi 版本兼容性与影响分析

> 记录上游 Pi 更新对本项目的直接影响和可改进点，供维护决策参考。

## 适用范围

本文档跟踪的 Pi 更新基线：**2026-06-09 发布版**

核心变更：
- Project trust（项目信任门控）+ `project_trust` 扩展事件

## 影响评估：🟡 可改进 — project_trust 自动信任提升多代理体验

### 变更详情

新增 `project_trust` 扩展事件：

```typescript
pi.on("project_trust", async (event, ctx) => {
  // event.cwd - 当前工作目录
  // ctx: { cwd, mode, hasUI, select, confirm, input, notify }
  if (await ctx.ui.confirm("Trust project?", event.cwd)) {
    return { trusted: "yes", remember: true };
  }
  return { trusted: "undecided" };
});
```

- 仅 **user/global 和 CLI `-e` 扩展** 参与（project-local 扩展在 trust 之后才加载）
- 返回 `"yes"` / `"no"` 则拥有决定权（首个 yes/no 获胜，抑制内置提示）
- `remember: true` 可持久化决定

### 与 dteam 的关系

dteam 是**多代理编排引擎**，核心场景：

| 场景 | 与 project_trust 的交互 |
|------|------------------------|
| 子代理启动时 cwd 切换到目标项目 | 每次切换可能触发 trust 检查 |
| 并行子代理访问不同项目目录 | 多个并发的 trust 弹窗可能打断工作流 |
| 用户已知某些项目是安全的 | 缺乏白名单机制时需反复确认 |
| `/resume` 恢复会话进入新 cwd | 可能重新触发 trust 流程 |

### 影响

| 维度 | 说明 |
|------|------|
| 用户体验 | 多代理工作流中频繁弹出 trust 提示 → **体验下降** |
| 功能正确性 | 不影响功能逻辑，但 trust 未通过时子代理无法加载项目资源 |
| 安全性 | 自动信任需要谨慎设计（白名单 / 规则 / 用户确认一次） |

### 建议动作

1. **[ ] 评估** dteam 作为 global extension 时是否应监听 `project_trust` 事件
2. **[ ] 设计** 信任策略选项：
   - **方案 A — 白名单模式**：维护已知安全路径列表，命中即 auto-trust
   - **方案 B — 委托模式**：首次由用户确认，`remember: true` 持久化
   - **方案 C — 透传模式**：不做任何拦截，完全交给 Pi 内置 trust 流程（当前行为）
3. **[ ] 实现** 如采用方案 A/B，在 `src/index.ts` 或 `src/session.ts` 中注册 `project_trust` handler
4. **[ ] 文档** 在 `doc/架构说明.md` 中补充 trust 策略说明

### 示例代码（方案 B — 委托 + 记忆）

```ts
// 在 extension 入口注册
pi.on("project_trust", async (event, ctx) => {
  // dteam 子任务通常访问用户自己的项目，默认倾向信任
  // 但仍给用户一次确认机会，之后记住决定
  if (!ctx.hasUI) return { trusted: "undecided" };

  const confirmed = await ctx.ui.confirm(
    "dteam: 信任此项目目录？",
    `子代理将访问: ${event.cwd}`
  );
  return { trusted: confirmed ? "yes" : "no", remember: confirmed };
});
```

### 优先级

🟡 **建议在 v0.5+ 评估实施** — 当前不影响核心功能，但多代理深入使用后体验改善明显。

## 次要关联

### Cache-hit Visibility（CH）

- Footer 新增缓存命中率显示。
- dteam 的 orchestrator 大量调用 LLM，CH 指标有助于调优 prompt 设计和 token 使用效率。
- **无需代码改动**，但可在 `reporter.ts` 中建议用户关注 CH 指标。

### Compaction Prompt 措辞（#5401）

- dteam 的子代理属于 **non-coding agent** 场景。
- 当 dteam 会话触发 compaction 时，Pi 内部现在会用中性 AI 助手措辞（不再偏 coding）。
- **正面影响**：dteam 的压缩摘要质量应该会有微升。
- **无需代码改动**。

### Skill Prompt 间距（#5371）

- dteam 不以 skill 形式分发，**无影响**。
