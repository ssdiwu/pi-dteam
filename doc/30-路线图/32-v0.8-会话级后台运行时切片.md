# 0.8 会话级后台运行时：实施切片

> **状态：✅ 已实施。** 以 [ADR 0009](../决策档案/0009-dteam重构为会话级后台运行时与星型信号协议.md) 和 [运行时蓝图](../10-架构与运行/15-dteam会话级后台运行时与信号协议.md) 为准；以下切片保留实施顺序和验收记录。
>
> 每个切片都是可单独验证的垂直路径；完成前不宣布 0.8 可用。

## 非目标

- 不做 workflow 引擎、Task Plan、自动决定下一 worker。
- 不恢复 Orchestrator Loop、Signal Store TTL、五角色、P2P worker 通信。
- 不做 resume、跨 Pi 进程持久化或常驻悬浮面板。
- 不预置或硬编码任何外部工具名。

## 切片 1：钉死 AgentSession 动态工具边界

**目标**：把“动态追加”限定为同一 session 中已注册候选工具的动态激活，并形成可回归的工厂契约。

- 新增最小测试：创建含 built-in、custom tool 与 unknown name 的 worker session；验证 active set 能撤销/恢复、unknown 不会静默被当成功。
- 新增候选工具校验：`baseTools ∪ addTools ∪ dteam_signal` 注册后，首次 prompt 前 active set 仅保留基础工具和 signal tool。
- 验证 `request_tools` 只能申请 `addTools`；非法名返回明确 `deny`。
- 调研并记录第三方 extension 的最小加载可行性；无法只加载候选 extension 时，0.8 不开放第三方候选工具，不能退化为全量加载。

**完成证据**：`npm test -- dynamic-tools` 覆盖同 session 激活、明确拒绝与首次权限收窄；`npm run build` 通过。

## 切片 2：会话级 Worker Manager 后台派发

**目标**：一次 `dteam` 立即受理一项或多项已就绪 worker 请求、后台运行，并保留现有档位、fallback、并发与 fresh 隔离。主代理决定哪些请求同时传入；dteam 不引入 batch 运行态或依赖图。

- 用 Worker Manager 接管旧同步执行路径；为 `dteam_dispatch({ workers: [...] })` 的每项请求创建 `queued → running → terminal` 的 `WorkerRecord`。
- `dteam_respond(...)` 只回应普通 waiting worker，`dteam_recover(...)` 只处理 timeout recovery；取消仍只走 `/dteam` 二次确认。
- 工具结果为每项 `DispatchAccepted`；成功完成 500ms–1s 聚合后 follow-up，失败立即 follow-up。
- 保持同档候选 fallback、五分钟 attempt 预算、十分钟 timeout recovery 累计上限和共享 Adaptive Concurrency；跨档由主模型按 T3→T2→T1 决定，轨迹写入 Worker Snapshot。
- 所有结束 worker 封存只读；Pi shutdown/reload 中止活跃 worker，不恢复。

**完成证据**：假的 worker executor 测试“立即返回、主会话可继续、成功合并、失败立即回传、shutdown abort”；原有路由 / 回退测试仍全绿。

## 切片 3：有类型 signal 与等待请求

**目标**：让 worker 的过程可观察、阻塞请求可真正暂停并由主代理恢复，但不引入编排循环。

- 实现 append-only Signal Log、Snapshot 投影与 Request State deferred。
- 实现 worker 专属 `dteam_signal` custom tool；校验 A/B/C 类 schema 与合法状态迁移。
- `progress`/`finding` 仅更新状态；`request_context` / `request_tools` / `request_decision` / `blocked` 立即 follow-up。
- `provide_context` / `grant_tools` / `deny` / `decision` 直接兑现同一 `dteam_signal` 阻塞调用的 deferred result；授权先变更 active tools 再恢复原 session。

**完成证据**：测试覆盖非阻塞不打断、阻塞 deferred、grant 后同 session 继续、deny 后可收口、过期 worker 拒绝 C 类 signal。

## 切片 4：`/dteam` Modal 与接管

**目标**：用户不靠日志也能查看、进入和安全接管 worker。

- 新增唯一 `/dteam` 命令：列表优先，选择进入详情 / Takeover View。
- 借 dgoal 的 overlay Modal：标题钉顶、正文滚动、`j/k` / 方向键、`Esc`；无常驻浮窗。
- 行展示：`title` 优先、显式 worker ID、状态、人类可读耗时、当前工具、实时摘要与主模型明确的档位轨迹。
- 运行中允许 steering；取消弹二次确认；结束记录只读。
- 状态栏仅在存在 queued/running/waiting worker 时显示。

**完成证据**：TUI 纯渲染函数测试覆盖运行区/历史区、详情、只读封存、取消确认；Pi 手工 smoke（冒烟）记录覆盖滚动、接管和状态栏隐藏。

## 切片 5：取消与端到端回传收口

**目标**：确保取消、聚合和真实 provider 行为都可预期。

- 取消从 `/dteam` 和主代理触发时一律二次确认；确认后 abort，写 `cancelled`，以 `reason: "user_cancelled"` 立即 follow-up。
- 合并窗口绝不吞失败、取消、阻塞请求；flush（刷新）条件可测。
- 跑至少一个 T3 后台成功、一个 request_context 恢复、一个 request_tools grant/deny、一个用户取消的真实 Pi smoke。
- 同步 README、API 参考、术语表、CHANGELOG 和版本号后，才发布 0.8。

**完成证据**：`npm run build`、`npm test`、Pi 加载、四条真实 smoke 日志及文档链接全部通过。

## 依赖与顺序

```text
切片 1（工具边界）
  └─ 切片 2（后台 Worker Manager）
       └─ 切片 3（signals / request）
            └─ 切片 4（/dteam Modal）
                 └─ 切片 5（取消、聚合、真实 smoke、发版）
```

任何切片失败先修该切片的反馈环；不得绕过切片 1 的权限边界直接加载所有 extension 来“让测试通过”。
