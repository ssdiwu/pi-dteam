## 暂不做（轻量化原则）

> 保留在路线图里，等痛点变强再升级到"要做"。每一项都标了"暂不做的理由"。

### 借鉴项

- **depth / cycle guard** — dteam 不递归 spawn subagent（in-process 架构）；chain 防重 task 是单独事，需要时单独评估
- **递归 usage tree** — 扁平统计够用；schema 兼容，需要时升级不复杂
- **check / adaptive 改 tool calling** — 正则"通过/pass/✓"够用，引入 tool calling 增加调用成本 + 错误处理

### 内部项

- **递归分解未接入** — brancher 复杂度过大，让 LLM 多轮解决（在 context window 内）
- **check/adaptive 凭正则判断** — 同借鉴项
- **极端大任务可能跑不完** — dteam 轻量化不解决，超大任务应拆为多次 dteam 调用
- **没有持久化** — in-memory 够用，进程崩了重跑

## 远期规划（结构性大改）

> 不是"不做"，是"未来某天再说"。这两项涉及多文件 + 启动开销等结构性改动，需要单独写方案。

- **persistence + resume** — 写盘 + 序列化 `SessionManager` + resume 检测。对方做在 `sessions-subagents/`，可以做在 `.dteam/sessions/`。
- **进程级隔离** — 把 `leaf.execute` 内部的 `createAgentSession` 换成 `spawn('pi', [...])`，子崩不影响主。涉及 `src/session.ts` 重写 + 信号通路（`SignalBus`）改造 + API key 透传策略调整。

## 更新原则

- 完成一项 → 把 `[ ]` 改成 `[x]`（借鉴部分），或在内部待办表里删行
- 范围变更 → 调整"对应范围"列
- 重要新项 → 加到对应范围段
- 暂不做 / 远期 项**不删除**——痛点变强时升级到对应档位
- 路线图变更尽量在独立 commit，方便回顾
