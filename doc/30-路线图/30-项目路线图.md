# 项目路线图

> 单一来源的演进计划。**v0.4.1 已完成并归档；下一阶段准备进入 0.5。**
>
> dteam 当前定位：Pi 里的轻量多 subagent（子代理）协作引擎；后台运行；5 角色写死；复杂任务才调用。

## 0. 版本窗口

| 窗口 | 定位 |
|---|---|
| `0.4.1` | ✅ 已完成：后台任务稳定性收口 |
| `0.4.2` | 文档校准 / 发布元信息 / 0.5 准备 |

## 1. 当前校准

1. **本质**：dteam 是 Pi 里的轻量多 worker 协作引擎。
2. **触发**：简单任务主 LLM 直接干；复杂任务才调 dteam。
3. **运行**：后台 run 返回 `runId`，进度走 `/dteam` 面板 / widget（小组件）/ 状态栏，完成后发 `dteam-report`。
4. **角色**：5 个角色写死是当前优势，不借鉴可配置 agent 市场。
5. **借鉴方式**：借轻动作，不照搬重系统。

## 2. 0.5 主线：轻量依赖图调度 + 运行态 UI

> 0.5 先解决“用户看得懂多 worker 正在干什么，以及为什么这样调度”。这吸收 SwarmFlow / MiMo Code 的核心启发：把可确定的协作关系交给系统执行，而不是全靠 leader agent 临场判断。

| 版本范围 | 优先级 | 事项 | 说明 |
|---|---:|---|---|
| 0.5.0 | P0 | `/dteam` 面板完成项清理 | 借 rpiv-todo：done 项保留到下一次 agent response / 下一次 run 前，再自动清理，避免“瞬间消失”和“永久堆积” |
| 0.5.0 | P0 | UI 状态收敛为 4 类 | pending / running / done / failed，对应当前 `idle` / `running` / `done` / `failed|error` |
| 0.5.0 | P0 | 轻量依赖图调度 | planner 给初始 `files`，dteam runtime 补轻量 import graph；显式同文件 / shared file / dependency edge 自动拆批；缺失 files 只标未知不阻塞 |
| 0.5.0 | P1 | 面板标题稳定显示 mode | 折叠态和展开态显示 `[solo]` / `[chain]` / `[team]`，用户知道当前组织形式 |
| 0.5.0 | P1 | report 按 worker tree 分组 | 最终 `dteam-report` 不只列 role，尽量保留 plan mode、worker 状态、失败摘要 |
| 0.5.1 | P1 | 自然语言使用示例 | 借 pi-subagents 的 “Try this first”：文档写清何时该让主 LLM 调 dteam |
| 0.5.2 | P2 | planner 英文关键词 fallback | 给 `quickRuleBasedPlan` 增加常见英文编码 / 并行 / 验证关键词 |
| 0.5.2 | P2 | 扁平 usage 统计 | 如 Pi 能可靠提供 usage，则在 `RunResult` 加单层 usage；不做递归 usage tree |

实施方案见：`../40-版本实施方案/41-v0.5.0-轻量依赖图调度与运行态UI实施方案.md`。

## 3. 0.5 可选增强（看真实痛点）

| 方向 | 条件 | 轻量做法 |
|---|---|---|
| 只读 status action | 用户经常问 run 状态但不想开面板 | 给 `dteam` 增加 `action="status"`，只读返回 active run 摘要 |
| `/dteam doctor` | 工具加载 / UI / report 常出问题 | 做只读诊断，不自动修改配置 |
| 共享文件 owner 扩展 | 显式同文件冲突治理仍不够 | 先做少量高风险共享文件模式，如 `package.json` / lockfile |
| Goal verifier | dteam 频繁“乐观完成” | 作为可选策略，不做固定流水线 |

这些不是 0.5.0 必须项。

## 4. 暂不做（轻量化原则）

> 保留，不删除。痛点变强时再升级。

| 项 | 暂不做理由 |
|---|---|
| 固定 6 阶段流水线（review / TDD / verify / merge） | 会把 dteam 拉回重型工业流程；未来 review / verify 应作为可选 worker 或策略 |
| 自定义角色 / agent 市场 | 当前 5 角色写死更稳定，能保护 build 唯一可写边界 |
| frontmatter 覆盖 ROLE_DEFAULTS | pi-subagents 这点好，但 dteam 当前不需要角色配置外放 |
| workflow.py / JavaScript workflow | SwarmFlow / MiMo 的编排脚本适合固定流程；dteam 先保持 planner + mode |
| Max Mode | token 成本高，个人工作流暂不需要 |
| check / adaptive 改 tool calling | 正则够用，引入 tool calling 增加失败面 |
| blockedBy 依赖追踪 | `chain` / `team` 已覆盖当前依赖表达 |
| 文件锁 / worktree / merge | 过重；0.5.0 只做轻量预检和拆批，不做隔离工作区或自动合并 |
| 进程级隔离 | 启动开销和 API key 透传复杂，远期再看 |

- 完成一项：移动到“已完成 / 已归档”或在 changelog 记录
