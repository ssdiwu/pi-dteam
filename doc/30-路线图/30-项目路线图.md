> 单一来源的演进计划。
>
> dteam 当前定位：**模型分级路由执行层**（[ADR 0008](../决策档案/0008-dteam重定位为模型分级路由执行层.md)）。主模型（T1）思考/路由/验收，小任务 fan-out 给小模型（T3）批量并行做，思考跟随档位，搞不定走 fresh 验收 → 回退强模型。

## 1. 当前校准（0008 定义）

1. **本质**：dteam 是模型分级路由执行层，不是通用 workflow platform，不是召唤池，不是对抗式合议。
2. **触发**：有大量小任务可分级并行加速用 dteam；单兵够用 + 需独立审核用 dgoal。
3. **边界**：dteam = 多模型分级路由；dgoal = 单模型建检。独立并列，不合并，不自动切换。
4. **运行**：主模型（T1）在对话里路由 + 调 dteam_dispatch fan-out + 收结果 + 按需 fresh 验收 + 回退。无独立 Orchestrator Loop。
5. **档位**：T1 思考 / T2 标准 / T3 快速（取代五角色），标准锚定供应商产品线层级。
6. **思考**：跟随档位（T1高/T2中/T3低），不独立成维；难任务走回退换强模型。
7. **工具**：单工具 `dteam_dispatch(task, tier, thinking?, tools?)`；执行/验收/回退都是它的用法。
8. **验收**：fresh 验收（dispatch 创建 fresh session，对抗主模型倾向）；复活 0007 的 fresh check 零件。
9. **回退**：硬失败自动 + 质量不过 fresh 验收触发；回退到 T1 或主模型自己。
10. **并发**：Adaptive Concurrency + Multi-Provider Routing（加 tier/thinking 字段）。

## 2. 0.6.0 召唤池重定义（已完成，定位被 0008 推翻）

0.6.0 把 dteam 从二维编排引擎改为"自发生长召唤池"（Orchestrator Loop + SignalStore + 强制 check）。代码已落地。**但该定位被 ADR 0008 推翻**（自发生长 → 对抗式合议 → 模型分级路由，三次重定位）。0.6.0 代码作为 0.7.0 改造的起点，不回滚。

决策骨架见 [`../决策档案/0005`](../决策档案/0005-dteam-0.6.0-重定义为自发生长召唤池.md)（仅追溯）。

## 3. 0.7.0 要做：模型分级路由重定位（ADR 0008）

> 代码从 0.6.0 Orchestrator Loop 形态改造为 0008 的 dispatch + T1/T2/T3。决策骨架见 [`../决策档案/0008`](../决策档案/0008-dteam重定位为模型分级路由执行层.md)。

| 方向 | 状态 | 说明 |
|---|---|---|
| 砍 Orchestrator Loop | 要做 | 删 `orchestrator-loop.ts` + 相关；主模型自己路由，不要独立 loop |
| 砍 Signal Store | 要做 | 删 `signals/*`；dispatch 是 fan-out + 收结果，不需要信号回流 |
| 砍对抗回合/积分制 | 要做 | 0006/0007 代码（如有）退场；保留 fresh check 零件到验收用法 |
| 五角色 → T1/T2/T3 | 要做 | `agents/*.md` + `session/role-config.ts` 改为档位配置（模型 + 思考 + 默认工具白名单） |

| Multi-Provider Routing 加 tier/thinking | 要做 | `session/model-routing.ts` + 档位配置加 tier + thinking 字段 |
| 对外工具更新 | 要做 | `index.ts` + `tools.ts` 重写为 dteam_dispatch |
| Adaptive Concurrency 保留 | 保留 | 并行 fan-out 需要 |
| 进程内 AgentSession + Logical Isolation | 保留 | dispatch 的实现基底 |

## 8. 更新原则

- 完成一项：移动到「已完成 / 已归档」。
- 新增事项：必须归类到 **要做 / 不做 / 已推翻 / 远期**。
- 已推翻项不删除，保留追溯链（指向推翻它的 ADR）。
- 路线图变更尽量独立 commit。
