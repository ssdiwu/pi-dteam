## 1. 当前校准（0.6.0 定义）

1. **本质**：dteam 是基于 goal 自发生长的多 worker 群策群力扩展，不是通用 workflow platform（工作流平台），不是预先穷举 plan 的执行引擎。
2. **触发**：简单任务主 LLM（主模型）直接干；需要群策群力（召唤多个专业角色）走 dteam。
3. **边界**：dteam = 群策群力（召唤池）；dgoal = 建检循环（单兵 + 独立审核）。独立并列，不合并，不自动切换。
4. **运行**：同步前台 Orchestrator Loop（编排循环）；放弃后台运行与 `runId`。
5. **主体**：Orchestrator（编排者）在 loop 内持续读 Signal Store（信号存储）并 LLM 驱动决定下一步召唤谁。
6. **worker**：进程内 `AgentSession`（代理会话）+ Logical Isolation（逻辑隔离）；不再默认 spawn（启动）OS 子进程。
7. **角色**：固定五角色 `explore / design / build / check / close`，不做角色市场。
8. **完成**：强制 `check` 角色（Completion Gate，收口闸门）收口；Orchestrator 不能自停。
9. **并发**：Adaptive Concurrency（自适应并发）+ Multi-Provider Routing（多供应商路由）。

## 2. 0.6.0 已完成：召唤池重定义

> 0.6.0 是一次定位级重定义。它的核心不是加功能，而是把 dteam 从「`solo/chain/team` × `direct/build_check/adaptive` 的二维编排引擎」改回它本来的「基于 goal 自发生长的召唤池」。决策骨架见 [`../决策档案/0005-dteam-0.6.0-重定义为自发生长召唤池.md`](../决策档案/0005-dteam-0.6.0-重定义为自发生长召唤池.md)。

| 方向 | 状态 | 说明 |
|---|---|---|
| 推翻 ADR 0003（后台运行） | 要做 | dteam 改为同步前台 Orchestrator Loop；`runId` / `RunsStore` / 立即返回式 run 失效 |
| 删除 `solo / chain / team` 与 `mode` | 要做 | 推翻二维编排组织维度；不再预先穷举 step |
| 删除 `SchedulingPlan` / `FileGraph` 主轴 | 要做 | 不再是编排核心；文件依赖可作未来辅助 |
| Orchestrator Loop 实现 | 要做 | 进程内主循环：读 Signal Store → LLM 驱动决策 → 召唤 worker → 收结果/信号 → 继续/收口 |
| 进程内 `AgentSession` worker | 要做 | worker 用 `createAgentSession` + `SessionManager.inMemory()` + 最小 ResourceLoader + 工具白名单 |
| Logical Isolation | 要做 | 用逻辑隔离替代 OS 子进程隔离，保证 worker fresh |
| Signal Store（TTL 衰减） | 要做 | 复用现有信号机制，worker 通过 `session.subscribe` 实时写入；TTL 衰减避免旧信号干扰 |
| Adaptive Concurrency | 要做 | 可同时召唤多 worker；参照 ant-colony `ConcurrencyConfig`（min/max/optimal/lastRateLimitAt） |
| Multi-Provider Routing | 要做 | 每角色可配主模型 + fallback 链，避免单供应商约 3 并发撞墙 |
| 强制 `check` 收口 | 要做 | 每个 goal 必须召唤 `check` 才算完成 |
| 启动方式 C 混合 | 要做 | `/dteam <goal>` 显式启动 + 主 LLM 自动拉起 |

## 3. 0.6.0 不做（本轮只动文档；代码改造是实施阶段）

| 项 | 暂不做理由 |
|---|---|
| `src/` 源代码改造 | 本轮（文档重构）只描述方向；代码改造是后续实施阶段，见 `42-v0.6.0-召唤池重定义实施方案.md` |
| 用户手写 `.dplan.*` / plan 文件 | 无预先 Task Plan；召唤轨迹即计划，不开放用户手写计划入口 |
| 固定流水线 / 6 阶段工业流程 | 会把召唤池重新拉回流水线 |
| 持久 Kanban / Harness 平台 | dteam 不做项目管理系统 |
| 角色市场 / 自定义角色 | 固定五角色，见 ADR 0002 |
| resume（恢复）/ 跨进程持久化 | 见 ADR 0004 |

## 7. 更新原则

- 完成一项：移动到「已完成 / 已归档」。
- 新增事项：必须归类到 **要做 / 不做 / 已推翻 / 远期**。
- 已推翻项不删除，保留追溯链（指向推翻它的 ADR）。
- 路线图变更尽量独立 commit。
