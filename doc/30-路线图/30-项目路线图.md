# 项目路线图

> 单一来源的演进计划。
>
> dteam 当前定位：**模型分级路由执行层**（[ADR 0008](../决策档案/0008-dteam重定位为模型分级路由执行层.md) + [ADR 0012](../决策档案/0012-主代理决策式逐级升级与超时恢复.md)）。主模型（T1）思考/路由/验收，独立小任务 fan-out 给小模型（T3）批量并行做；主模型汇总结果后按 T3→T2→T1 明确逐级升级。
>
> 与 [`pi-dgoal`](../../../pi-dgoal) 独立并列：dteam = 多模型分级路由，dgoal = 单模型建检循环。
>
> **0.7 实施状态**：T1/T2/T3 fresh dispatch、档位路由、超时/取消回退、并发与唯一公开工具均已实现并有测试；0.6 runtime/UI 已删除。

## 1. 当前校准（0008 定义）

1. **本质**：dteam 是模型分级路由执行层，不是通用 workflow platform，不是召唤池，不是对抗式合议。
2. **触发**：有大量小任务可分级并行加速用 dteam；单兵够用 + 需独立审核用 dgoal。
3. **边界**：dteam = 多模型分级路由；dgoal = 单模型建检。独立并列，不合并，不自动切换。
4. **运行**：主模型（T1）在对话里路由 + 调 `dteam` fan-out + 收 follow-up 结果 + 按需 fresh 验收 + 回退。无独立 Orchestrator Loop。
5. **档位**：T1 思考 / T2 标准 / T3 快速（取代五角色），标准锚定供应商产品线层级。
6. **思考**：跟随档位（T1高/T2中/T3低），不独立成维；难任务走回退换强模型。
7. **工具**：单工具 `dteam({ type: dispatch | respond, ... })`；派发和回应共用一个工具，`/dteam` 只做用户管理。
8. **验收**：fresh 验收（dispatch 创建 fresh session，对抗主模型倾向）；复活 0007 的 fresh check 零件。
9. **回退与升级**：同档候选自动用于可用性；异常、质量问题与 timeout 回传主模型，由其决定重试、fresh 验收或 T3→T2→T1 相邻升级。
10. **并发**：Adaptive Concurrency + Multi-Provider Routing（加 tier/thinking 字段）。

## 2. 0.6.0 召唤池重定义（已完成，定位被 0008 推翻）

0.6.0 把 dteam 从二维编排引擎改为"自发生长召唤池"（Orchestrator Loop + SignalStore + 强制 check）。代码已落地。**但该定位被 ADR 0008 推翻**（自发生长 → 对抗式合议 → 模型分级路由，三次重定位）。0.6.0 代码作为 0.7.0 改造的起点，不回滚。

决策骨架见 [`../决策档案/0005`](../决策档案/0005-dteam-0.6.0-重定义为自发生长召唤池.md)（仅追溯）。

## 4.1 0.8 已实施：会话级后台运行时（ADR 0009）

0.8 只把 0.7 的同步单任务执行升级为会话级后台 worker：主代理派发后继续对话，worker 用有类型 signal 请求最小上下文、预授权工具或决策；完成成功结果短窗汇聚，失败/取消/阻塞立即回传。Worker Manager 管理生命周期和可观察性，不做下一轮任务的编排决定。

| 切片 | 目标 | 验收重点 |
|---|---|---|
| 1 | 动态 active-tools 边界 | 只激活已注册 `addTools` 候选，未知名 fail-closed |
| 2 | 会话级 Worker Manager | 立即受理、后台执行、结束回传、会话关闭中止 |
| 3 | A/B/C 有类型 signal | request 真暂停，主代理回应后由原 session 继续 |
| 4 | `/dteam` Modal / Takeover View | 列表、详情、steering、取消确认、结束只读 |
| 5 | 取消和真实冒烟 | `user_cancelled`、聚合窗口及四条真实路径可复验 |

详细顺序和非目标见 [`32-v0.8-会话级后台运行时切片.md`](./32-v0.8-会话级后台运行时切片.md)。

## 8. 更新原则

- 完成一项：移动到「已完成 / 已归档」。
- 新增事项：必须归类到 **要做 / 不做 / 已推翻 / 远期**。
- 已推翻项不删除，保留追溯链（指向推翻它的 ADR）。
- 路线图变更尽量独立 commit。
