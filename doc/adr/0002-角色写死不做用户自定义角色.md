# 角色写死，不做用户自定义角色

dteam 把协作角色写死成 `explore` / `design` / `build` / `check` / `close`，不借鉴 pi-subagents（Pi 子代理扩展）的 frontmatter（前置元数据）可配置角色体系。

**背景**：pi-subagents 支持用 markdown frontmatter 定义 agent、override（覆盖）模型 / 工具 / prompt（提示词）。这对通用插件有价值，但 dteam 当前只解决 507 的个人编程复杂任务。

**决定**：角色写死，工具权限写在代码里（`src/session/role-config.ts` 的 `ROLE_DEFAULTS`）。

**为什么**：
- 5 个角色已覆盖当前工作流。
- 写死更容易验证 `build` 唯一可写这条安全边界。
- 避免角色数量膨胀导致 planner（规划器）输出不稳定。

**权衡**：牺牲了灵活性和前端可配置性；换来安全边界可验证、planner 行为可预测。如果未来真实痛点证明 5 角色不够，再单独写方案评估局部 override，而不是现在提前抽象。

**关联**：`doc/10-架构与运行/11-角色系统.md` 第 2、6 节。
