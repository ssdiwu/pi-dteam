# 不做 resume 和默认持久化

dteam 不提供任务 resume（恢复）和默认持久化。Pi 进程退出后，active run（进行中的运行）丢失。

**背景**：多 worker 协作系统通常会用持久化 task store 支持崩溃恢复和 resume。这看起来是"应该有"的能力。

**决定**：当前不做 resume 和默认持久化。只有 plan（计划）和 scheduling（调度）checkpoint 会写入 Pi session entry（会话条目），用于 UI 回放，不用于恢复执行。

**为什么**：
- dteam 当前要解决的是 507 个人编程复杂任务，单次会话内完成是常态。
- resume 会引入跨进程状态一致性、部分完成回滚、幂等重放等重型问题，复杂度远超当前收益。
- plan / scheduling checkpoint 已经足够让人理解一次 run 发生了什么。

**权衡**：牺牲了崩溃恢复和长任务续跑能力；换来实现简单、不需要引入持久化存储和一致性协议。如果未来出现真实的长程任务恢复痛点，再单独写方案，不提前抽象。
