# dteam 档位系统（T1/T2/T3）

> 0008 重定位后，dteam 内部的"角色"= **模型能力档位**（T1/T2/T3），取代旧的五角色职能分工（explore/design/build/check/close）。
>
> 决策见 [ADR 0008](../决策档案/0008-dteam重定位为模型分级路由执行层.md)。档位是 dteam 路由的执行单元，由 `dteam_dispatch` 按需创建。

## 1. 三档位

| 档位 | 模型 | 思考 | 默认工具 | 用途 |
|---|---|---|---|---|
| **T1 思考档**（frontier） | 旗舰 | 高 | 全工具（读写改 + 审核） | 思考 / 决策 / 综合 / 路由 / 验收 / 回退重做 |
| **T2 标准档**（standard） | 标准 | 中 | 可写（读写改） | 常规实现 |
| **T3 快速档**（fast） | 快速 / 本地 | 低 | 默认只读；显式限定写 | 机械小任务 |

- **标准锚定供应商产品线层级**：每家供应商都已分好旗舰/标准/快速三线，dteam 映射即可。价格为辅验证。
- **思考跟随档位**：T1高/T2中/T3低。理由：思考收益随档位降低而递减（小模型高思考不划算）；难任务走回退换强模型（自带高思考），不是让小模型多想。
- **档位本质是人为划档**（模型能力连续，档位离散近似），不是客观物理边界。
- dispatch 可覆盖默认配置（如 T3 临时给可写权限做独立模块小改）。

## 2. 为什么是档位而不是五角色

旧五角色（explore/design/build/check/close）是**职能分工**——谁探索、谁设计、谁实现、谁验收、谁收口。这是流水线/对抗视角的产物（0.5.0/0.6.0/0006），已被 0008 放弃。

档位是**能力分级**——按任务难度匹配模型智力档位。这和 0008 的定位（模型分级路由）自洽：dteam 的价值就是"小任务不该用强模型"，档位是这件事的直接表达。

## 3. 工具权限矩阵（按档位默认）

实际档位配置已写入 `src/session/tier-config.ts`；以下矩阵是当前 0.7 dispatch 内核默认：

| 工具 | T1 思考 | T2 标准 | T3 快速 |
|---|:---:|:---:|:---:|
| `read` | ✅ | ✅ | ✅ |
| `bash` | ✅ | ✅ | ❌（仅 `tools` 显式授予） |
| `grep` / `find` / `ls` | ✅ | ✅ | ✅ |
| `write`（新文件） | ✅ | ✅ | ❌（仅 `tools` 显式授予） |
| `edit`（改现有文件） | ✅ | ✅ | ❌（仅 `tools` 显式授予） |
| 审核相关（跑测试/查证据） | ✅ | ❌ | ❌ |

说明：
- T1 全工具，因为它负责验收/回退（要能查证据 + 重做）。
- T3 默认只读——它做机械小任务；仅独立小改可由 dispatch 的 `tools` 显式授予限定 `edit` / `write`。
- 调用方显式 `tools` 是最高安全上限：dispatch 与回退只能取其子集；不传时回落档位默认。

## 4. fresh 验收（取代旧 check 收口）

旧 `check` 角色是强制收口闸门（Completion Gate），已被 0008 推翻。取代它的是 **fresh 验收**——但它不是独立角色/工具，是 `dteam_dispatch` 的一个用法：

```
验收 = dteam_dispatch(T1, "验收这个产出是否达标", 只读工具)
```

dispatch 创建的 worker 都是 fresh session（Logical Isolation，不继承主会话），所以验收 worker 天然看不到主会话/方案出处——对抗主模型"既是分配者又验收"的倾向。

这是 dgoal「不让学生判卷」原则从"完成判定"迁移到"路由+验收"。**复活自 ADR 0007 的 fresh check 零件**（不是回到对抗式合议整体）。

验收默认可选（A 形态要轻）；真关键的 task 主模型显式调 fresh 验收。

## 5. 为什么不做角色市场

档位写死成 T1/T2/T3，不开放用户自定义角色。理由（延续 ADR 0002 精神）：

| 选择 | 原因 |
|---|---|
| 三档写死 | 覆盖"思考/常规/机械"全谱，对应供应商已有的产品线分层 |
| 工具权限按档位 | 容易验证安全边界 |
| 不做自定义角色 | 避免档位膨胀、路由决策不稳定 |
| 模型可配（Multi-Provider Routing） | 每档可配主模型 + fallback 链，应对并发墙 |

## 6. 档位配置

档位配置已写入 `src/session/tier-config.ts`：T1/T2/T3 默认 thinking、工具白名单、独立 system prompt 与显式模型主链/FallbackModels 配置。旧 `src/session/role-config.ts` 仅供 0.6 loop 过渡，待旧运行时删除。

旧 `agents/*.md`（explore/design/build/check/close）仍待随五角色执行链退场；不再改造成新的档位 prompt 文件。

## 7. 修改档位的原则

1. 先确认是否真的需要改档位，而不是改 dispatch 参数或 prompt。
2. 如果涉及工具权限，注意 T3 默认只读的安全边界。
3. 不新增档位，除非有 3 次真实任务证明三档不够（延续 ADR 0002 精神）。
4. 改档位后必须同步：`src/session/tier-config.ts`、本文档、术语表。
