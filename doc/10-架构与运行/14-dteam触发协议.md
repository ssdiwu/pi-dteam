# dteam 触发协议

> 目的：让主 LLM 在面对任务时有明确 routing rule（路由规则），并在 dteam 与 dgoal 之间正确选择。
>
> 0008 重定位后：dteam = 多模型分级路由（小任务甩给小模型批量做，强模型思考/验收）；dgoal = 单模型建检（单兵 + 独立审核）。两者独立并列。
>
> **实施状态**：本协议描述当前 0.8 路由行为；T1/T2/T3 fresh dispatch、公开 `dteam`、后台 Worker Manager、回退与并发均有测试，旧 0.6 runtime 已删除。

## 1. 一句话规则

> **简单任务主 LLM 直接做；单兵能持续推进 + 需独立审核走 dgoal；有大量小任务可分级并行加速（甩给小模型批量做）走 dteam；用户明确说"用 dteam / 用 dgoal"时必须尊重。**

## 2. dteam vs dgoal 判断（核心）

| 判断 | 走哪个 |
|---|---|
| 单代理能干，自己推进即可 | 主 LLM 直接做 |
| 单兵推进 + 需要独立零上下文终审 | **dgoal**（单模型建检） |
| 有大量小任务可分级并行加速（甩给小模型批量做，省强模型） | **dteam**（模型分级路由） |
| 用户明确说"用 dteam" | **dteam** |
| 用户明确说"用 dgoal / /dgoal" | **dgoal** |

两者独立并列，不合并，不自动切换。主 LLM 自己判断。

## 3. 必须触发 dteam

命中任一强触发条件时，主 LLM 应进入 dteam 分级路由（调 `dteam`）：

| 强触发条件 | 说明 |
|---|---|
| 用户明确说"用 dteam / 走 dteam / 让 dteam 做" | 用户显式指定优先级最高 |
| 有一批独立小任务可并行（refactor 批、UI 优化批、独立模块小改、批量 bug） | 这是 dteam 的本质——甩给 T3 小模型批量做，强模型只做思考和综合 |
| 任务里有大量机械性、可拆分的小活 | 小模型（T3）胜任，不该用强模型（贵 + 慢） |

## 4. 默认触发 dteam

没有强触发，但命中以下条件中任意 2 条，默认应走 dteam，除非用户明确要求"你直接做"或"用 dgoal"。

| 判断项 | 例子 |
|---|---|
| 一批 refactor / UI / 小改任务 | Curio 式的页面下沉、交互优化、独立模块收口 |
| 多个模块/文件的独立小改 | 可并行 fan-out 给 T3 |
| 任务里明显有"机械活"占大头 | 强模型该专注思考和综合，机械活甩给小模型 |
| 有明确成本意识（不想烧强模型 token） | 小模型批量做省成本 |

## 5. 不应该触发 dteam

| 场景 | 推荐做法 |
|---|---|
| 普通问答 / 解释代码 | 主 LLM 直接回答 |
| 单文件小改 | 主 LLM 直接改 |
| 单兵能干 + 只需独立审核 | 走 dgoal，不是 dteam |
| 任务强依赖、无法并行（前后衔接） | 主 LLM 串行做（dteam 并行无收益） |
| 只做方案评审，不实施 | 主 LLM 先分析 |
| 用户要求"你先别改代码" | 不调 dteam |

## 6. 触发前的主 LLM 自检

主 LLM 在决定是否进入 dteam 分级路由前，应快速问自己：

```text
1. 这批任务里有没有大量"机械性、可拆分"的小活？（有 → T3 批量做）
2. 这些小活之间文件是否独立？（独立 → 可并行 fan-out）
3. 能否先拆成多个独立事实搜集项？（能 → 优先 T3 批量做，收结果后再决定下一轮）
4. T3 结果不足但目标已清楚吗？（是 → 主代理派 T2；仍需复杂决策/验收才派 T1）
5. 单兵能干 + 只需独立审核吗？（能 → dgoal，不是 dteam）
```

## 7. 用户显式触发语句

以下说法都视为强制触发 dteam：

```text
用 dteam 做这个
这个任务走 dteam（并行加速）
把这批小任务甩给小模型批量做
用 dteam 分级路由
```

以下说法视为走 dgoal：

```text
用 dgoal 做这个
/dgoal <目标>
```

## 8. 示例

### 8.1 应触发 dteam：一批独立 refactor

用户：

```text
把 Curio 这组 refactor 做了：#55 页面下沉、#59 订阅边界、#60 IS-Net 隔离、#48 星级视觉。
```

判断：一批独立小任务，可分级并行。#55/#59 可甩 T3，#60 改 VisionKit 包文件独立也可 T3，关键的验收走 T1 fresh。

结果：应进入 dteam 分级路由。

### 8.2 走 dgoal：单兵 + 独立审核

用户：

```text
/dgoal 把这个 README 的错别字全改了，改完独立审核一遍。
```

判断：单兵能干 + 需要独立终审。

结果：走 dgoal，不是 dteam。

### 8.3 不触发：强依赖串行任务

用户：

```text
先探索这个模块，再设计方案，再实现，每步依赖上一步。
```

判断：强依赖串行，并行无收益；单兵推进 + 独立审核更合适。

结果：走 dgoal 或主 LLM 直接串行做，不调 dteam。

### 8.4 不触发：单文件小改

用户：

```text
把 README 里 dteam 的一句介绍改得更短。
```

判断：单文件文案小改。

结果：主 LLM 直接做。

## 9. 边界

dteam 触发协议不是为了把所有任务都变重。它只解决一个问题：

> 当任务的效率瓶颈是"强模型在做本该小模型做的机械活"时，主 LLM 应进入 dteam 分级路由——优先甩给多个 T3 批量搜集事实，汇总后按需要逐级派 T2、T1，强模型专注思考/综合/验收。

因此 dteam 仍不做：

- 持久 Kanban / 企业级 Harness / 固定流水线
- Orchestrator Loop / Signal Store / 对抗回合（已被 0008 推翻）
- 角色市场（T1/T2/T3 三档写死）
