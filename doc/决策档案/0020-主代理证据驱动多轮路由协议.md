# 主代理证据驱动多轮路由协议

> **状态：✅ 有效，协议与文档本轮落地；外部只读联网 worker 与 routing benchmark 待后续验证。**
>
> **更新**：补充 ADR 0008 的产品合同、ADR 0014 的 T3-first 触发形态与 ADR 0016 的结果后路由；不改变 ADR 0010 的“不保存 batch / 依赖图”、ADR 0004 的“不做 resume”或 Worker Manager 只管理已派发 worker 的边界。

## 决定

dteam 的正式合同由两部分组成：

1. **模型分级执行层**：Worker Manager 负责已派发 worker 的档位、工具、后台生命周期、signal、报告、等待、恢复与回传。
2. **主代理的证据驱动路由协议**：主代理负责理解目标、选择当前需要取得的证据、分轮派发、综合报告、决定实现档位、判断验证结果并收口。

路由协议是规范性默认，但用户明确要求直接处理、指定档位、使用 dgoal 或不调用 dteam 时优先服从。它不成为 runtime 的自动状态机或语义硬门。

## 多轮 T3 探索

凡非极小代码任务且仍需从仓库取得事实，主代理默认先派一轮相互独立、只读的 T3 worker。第一轮按当前目标需要选择不同证据面，例如架构与模块边界、入口与调用链、测试与配置、既有实现或复用风险；不是每次固定召唤所有视角。

主代理汇总并裁决第一轮事实后，才为新暴露的具体未知派下一轮 fresh T3。事实足够后，独立机械小改可交 T3，已定位的常规实现交 T2，复杂判断或高风险收敛交 T1。Worker Manager 不知道轮次、前沿、依赖或后继任务。

Ponytail 式“仓内已有 → 标准库 → 原生平台 → 已安装依赖”只作为存在过度实现风险时的一种有界探测视角，不注入每个 T3 的固定 prompt。

## 外部信息取证

外部事实遵循：**主代理定义问题并选择可信来源，T3 对已选来源做受限只读提取，主代理负责综合、反证与冲突裁决。**

当前 worker 的第三方 extension 工具仍被 `tool-policy.ts` fail-closed 拒绝。因此现阶段由主代理先搜索、抓取或 clone 来源到可读位置，再派 T3 分析；未来只有在受限只读联网工具完成安全加载、提示注入与来源边界验证后，才允许 T3 直接读取已知 URL。不得让 T3 独占来源选择与最终判断。

## 用户决策与耐久地图

只能由用户决定的产品意图、风险承受或不可逆取舍留在主代理 / 用户对话中，不预先派给 worker。worker 执行时意外发现决策缺口，仍通过结构化 request 回到主代理。

跨会话的大型目标可以由 dgoal plan、issue、PRD、spec 或项目既有地图保存目标、决策与依赖。主代理只把当前切片和必要证据指针写入 `task` / bounded handoff 后交给 dteam。dteam 不保存外部 ID 映射，不更新依赖图，不恢复旧 worker session；耐久决策工件与 runtime resume 是两件事。

## 结果后路由

主代理根据结构化工作报告的任务完成程度、实际动作、验证深度、验证结果、剩余未验证项和不确定性，决定收口、补充取证、fresh 重试、相邻升级、请求用户决策或记录可复用经验。Worker Manager 只回传事实，不自动作出这些决定。

## 代价与验证

这项决定扩大了 dteam 对主代理行为的责任范围，也增加了路由 prompt、文档和评测负担；换来的是 T1 不再亲自串行探索、低档证据能驱动下一轮、长期项目可以引用外部地图而不把 Manager 变成编排器。

后续必须建立 routing benchmark，对比 `T1 direct`、`T2 direct`、`T3-first` 与 `T3→T2` 的质量、总成本、延迟、升级率和重复探索。benchmark 是证伪与校准机制，不阻止本 ADR 落地；若数据反对默认 T3-first 或某类多轮探测，后续 ADR 应收窄或推翻本决定。

## 明确不做

- 不恢复 Orchestrator Loop、Signal Store TTL、五角色或固定流水线；
- 不把多轮、依赖、外部地图或 dgoal task 写入 Worker Manager；
- 不为“前沿”新增 `frontierState`、`taskType`、`mapId` 或自动派发；
- 不把完整主会话、完整 transcript 或外部地图全文注入 worker；
- 不把来源选择、用户决策或最终收口下放给 T3。
