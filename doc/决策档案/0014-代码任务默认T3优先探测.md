# 代码任务默认 T3 优先探测

> **状态：已定，待下一主版本实施**
>
> **更新**：更新 ADR 0008 的“主模型路由 + T3 批量执行”默认触发形态与当前触发协议中的高门槛；不改变 ADR 0013 的三工具面、ADR 0012 的主代理恢复决策或“不做 Orchestrator Loop”。

下一主版本采用 **T3 → T2 → T1 的递增成本纪律**。主模型始终先理解用户目标、上下文、约束与验收，再将需要从当前仓库取得事实的非极小代码任务拆成 1–3 个有界、独立、只读的 T3 代码探测。T3 也可在显式 `addTools` 最小授权内完成独立的机械小改；仅当 T3 的事实或执行能力明确不足，才由主模型逐级派发 T2，再到 T1。

T2 只承接已由 T3 定位、边界清晰的常规实现，不应重新做宽泛探索。T1 仍是 routing 和综合 owner，但不应亲自承担文件搜索、调用链定位或普通实现；仅处理复杂判断、高风险收敛、复杂重构与验收。单文件不是 T1 的充分条件，只有语义复杂、难以验证或风险高的单文件改动才应升档。

纯概念问答、用户已给出完整证据的回答，以及精确单文件的极小读取可由主模型直接完成。该纪律不是 runtime 自动派发：Worker Manager 不根据关键词或文件数自主创建 worker，不引入 planner、任务图、轮询或编排循环。用户明确要求直接处理、使用 dgoal 或不调用 dteam 时优先尊重。

代价是额外的小模型调用和短暂等待；换来主模型不再串行承担低价值代码定位，并把 T1 时间集中于判断、综合、实施边界与验收。
