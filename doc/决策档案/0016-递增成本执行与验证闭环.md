# 递增成本执行与验证闭环

> **状态：已定，待下一主版本实施**
>
> **更新**：更新 ADR 0008 中“仅关键任务派 T1 fresh 验收”的默认形态；补充 ADR 0014 的 T3 → T2 → T1 路由纪律与 ADR 0015 的结构化交接。

下一主版本的 dteam 回路是：主模型持续理解用户目标、上下文、约束与验收，负责拆题、路由、证据筛选、冲突裁决和最终收口；T3 先并行收集代码证据。主模型根据证据将实现任务交给最低足够档位——独立机械小改给 T3、边界清晰的常规实现给 T2、复杂或高风险重构给独立 T1 worker。主模型即使自身使用 T1 思考档，也不与被派发的 T1 worker 混同；T1 worker 不因文件数量或单文件形态默认承接实现。

完成后按同一递增成本纪律派发 fresh 验证 worker：T3 核对机械条件、测试、diff 和明确要求；T2 审查行为与跨模块实现；仅在高风险、证据冲突或低档验证仍无法确定时派 T1。验证 worker 不能是实现该变更的同一 worker session；失败报告经 ADR 0015 的结构化报告与有界 handoff 成为下一轮的输入。

该闭环不引入固定流水线、自动升级或 Completion Gate（完成闸门）。主模型仍根据用户目标、T3 事实和验证证据决定是否派发、升级或收口；代价是更多低档 worker 调用，换来不让昂贵 T1/T2 承担低价值探索、普通实现和机械验收。
