> **推翻**：[ADR 0005](./0005-dteam-0.6.0-重定义为自发生长召唤池.md) 第 17 条（每轮 LLM 现场决策召唤谁）——协调层确定化。
> **外部依据**：507 vault 判断体系——`01-碎片/聚合质量才是多模型协作的杠杆不是多样性.md`（selection 碾压 synthesis，arXiv 2603.20324 + 2502.00674）、`01-碎片/协调能学判断不能学.md`（协调可程序化、判断不可学）。

## 1. 一句话决定

对抗式合议用**固定回合骨架 + 多轮积分淘汰制**收敛方案：每个合议单元走多轮「证据→主张→反方→裁决」，裁决用 **selection 打分累计**（非 synthesis 融合），先到 5 分且至少 3 轮者胜出。协调层由 runtime 确定化，判断层保留 LLM 智能。

## 2. 核心机制

### 2.1 协调层确定化（推翻 0005 第 17 条）

借鉴「协调能学判断不能学」：协调（调谁、回合怎么走、积分规则、收敛条件）是**可程序化的**，交给 runtime 驱动，不让 LLM 每轮重新拍板召唤谁。只有判断（出方案、提质疑、打分）保留 LLM 智能。这是确定性锚点的来源。

### 2.2 合议单元与回合骨架

**合议单元**：一个需要对抗的决策点。一个目标可拆成多个合议单元。

**回合骨架（固定，枚举变体有限）**：

```
回合 r = 1..maxRounds
① 证据  explore   → 事实/约束摘要 → 广播所有 design
② 主张  design ×N  → 各出独立方案（彼此 fresh 隔离）
③ 反方  build     → 对每方案提可行性质疑
        check    → 对每方案提风险质疑
④ 裁决  close     → selection 打分 + 累计 + 生成 summary（不转原文）
⑤ 收敛  ≥5 分 且 ≥3 轮 → 胜出收敛；否则 summary 进 r+1；达 maxRounds 取最高分
─── 单元收敛后执行闭环 ───
⑥ 落地  build     → 承接胜出方案执行（盯死不背叛）
⑦ 盯一致性 check  → 带上下文审"执行是否背叛对抗方案"
⑧ 收口  close     → 最终确认
```

### 2.3 积分制（selection，非 synthesis）

借鉴「聚合质量才是杠杆不是多样性」：两篇 arXiv 反例证明 judge-based selection 在 42 任务全赢，synthesis 融合输给单模型 80%——**融合毁掉对抗产生的差异信号**。故 dteam 裁判用 **selection**，绝不把多方方案融合成妥协方案。

**积分规则**：
- 大幅胜出：胜出方 **+2**
- 平局或单个微弱胜出：相关方案各 **+1**（可多名同加）
- 本轮未胜出：**+0**
- 总分上限 **5 分**，至少 **3 轮**才允许收敛

**多轮 selection 比一次性 selection 稳**：防单轮偏差，方案在反馈中进化。确定性收敛点 = 先到 5 分（可复验）。

### 2.4 N design 差异化（防趋同，积分制的物理基础）

碎片警告：selection 要吃到方案方差，若 N 个 design 趋同则无得选，退化成单方案。防趋同从两维度制造差异：

- **模型维度**：N 个 design 用不同模型（主模型 + 不同 fallback），呼应 Multi-Provider Routing。
- **prompt 偏好维度**：不同 system prompt 强调不同偏好（如稳健型 / 激进型）。

**两者都做**，因为"不是所有用户都持有多个模型"——单模型用户靠 prompt 偏好维度也能制造差异，不把 dteam 锁死在多模型持有者上。

### 2.5 close 用 fresh 子进程独立裁判

close 承担 selection 打分，必须中立，不被自己的模型偏好污染。强制用独立 `AgentSession` + fresh 上下文（借鉴 dgoal 的 fresh 子进程防自证机制），只见"各方案 + 反方质疑"，不见"哪个 design 在第几轮说了什么"，打分前不知道方案出处/历史，防偏好锚定。

这让 dteam 第一次有了和 dgoal 同源的可靠性手法——close 是 mini 版独立审核员，只是审"方案质量+漂移"而非"DoD 达标"。

### 2.6 summary 不转原文（防污染）

裁决反馈发给各 design 时**只发 summary 摘要，不转原文**。呼应碎片1：发原文会让方案互相污染、趋同，丢掉对抗产生的多样性信号（synthesis 陷阱）。发摘要 = 保留"知道对手好在哪"的反馈 + 维持各 worker 的 fresh 隔离。

## 3. 确定性锚点（本 ADR 的核心交付物）

对抗式合议的确定性来自两个可复验的锚点：
1. **收敛条件确定**：先到 5 分且至少 3 轮 = 收敛，不是"LLM 感觉够了"。
2. **四视角到位确定**：证据方/主张方/反方/裁决都出过声，可验证回合完整性。

加 ADR 0006 的锚点（执行不背叛、分歧解决），共四个确定性锚点。

## 4. 权衡

| 取舍 | 代价 | 换来 |
|---|---|---|
| 协调层确定化 | 牺牲每轮自由召唤 | 确定性锚点（可用性前提） |
| selection 非 synthesis | 不产出"融合各方优点"的新方案 | 保留对抗产生的差异信号（反例证明融合反而降质） |
| N design 差异化 | 多模型/prompt 配置面 | 积分制有方差可选（物理基础） |
| close fresh 子进程 | 多一次独立召唤开销 | 裁判中立，分数可信 |
| 5 分上限 / 3 轮下限 | 比"直到满意"硬 | 确定收敛点，防无限拖 |
| summary 不转原文 | 各 design 看不到对手原文 | 防污染，保护多样性 |

## 5. 待定分支（本次对齐未覆盖，留后续 grill / 实施方案）
