## 目标
- 为什么: dteam 当前 SignalBus 仅在内存（src/P1/signalBus.ts history: Signal[]），background worker 派生的子进程互相看不到信号；task Markdown 不适合承载高频低价值的进度/警告/发现事件流。设计任务 mtgl 已给出 5 个 milestone 拆分 + 兼容性矩阵，本 task 实施 M1-M3：P0 类型层 + P1 服务层 + P2 桥接层，让团队协作可追溯、可审计、可跨进程读。
- 做什么: 在 dteam 实现属于 dteam 的「信息素层」——SignalLog（追加日志）+ EventStream（SignalBus↔SignalLog 桥接），复用现有 4 信号类型和 P0 原子层。范围严格控制在 M1-M3：M4 worker_start/cancel 接入和 M5 widget 增强留作后续 task。
