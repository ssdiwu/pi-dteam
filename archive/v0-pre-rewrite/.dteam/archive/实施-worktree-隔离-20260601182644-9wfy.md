## 目标
- 为什么: dteam 当前并行 worker 改同一 git 仓库会冲突（src/P2/team.ts:33 用 mapWithConcurrencyLimit 并行运行多个 worker，没有文件级隔离）。subagents 用 git worktree 解决，any 用文件锁，dteam 现在两样都没有。并行 build/check 阶段高概率踩坑。
- 做什么: 为 dteam 并行 worker 引入 git worktree 隔离：worker_start 时如果 worker 配置声明 worktree: true 且 cwd 是 git 仓库，自动创建 worktree 分支、worker 在 worktree 中运行、worker 完成后可选自动 merge 或保留分支给用户决策。

## 阶段记录### 探索发现

#### 当前并行执行

- `src/P2/team.ts`：使用 `mapWithConcurrencyLimit` 并行运行多个 worker
- 所有 worker 共享同一个 cwd，没有文件级隔离
- 并行修改同一文件会冲突

#### Git Worktree 机制

- `git worktree add <path> <branch>`：创建 worktree
- `git worktree remove <path>`：删除 worktree
- 每个 worktree 有独立的工作目录和索引
- 适合并行开发场景

### 讨论决策

#### 实现方案

1. 扩展 WorkerConfig：新增 `worktree: boolean` 和 `worktreeAutoCleanup: boolean`
2. 修改 `src/P2/worker.ts`：worker_start 时如果 worktree=true 且 cwd 是 git 仓库，自动创建 worktree
3. 新增 `src/P1/worktree.ts`：封装 git worktree 操作

#### Worktree 生命周期

```
worker_start(worktree=true)
  ↓
检查 cwd 是否是 git 仓库
  ↓
创建 worktree 分支 dteam/<workerId>
  ↓
worker 在 worktree 路径中执行
  ↓
worker 完成/失败/取消
  ↓
保留 worktree（默认）或自动清理（worktreeAutoCleanup=true）
```

#### 命名规则

- 分支名：`dteam/<workerId>`
- Worktree 路径：`<cwd>/.dteam/worktrees/<workerId>`

#### 清理策略

- 默认保留 worktree，给用户检查
- `worktreeAutoCleanup=true` 时自动清理
- 提供 `worker.worktreeCleanup()` 显式清理

#### 兼容性

- `worktree: boolean` 默认 false，老调用方不传走原行为
- 不影响现有 solo/chain/team 模式
