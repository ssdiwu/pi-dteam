## 目标
- 为什么: dteam 当前是"用户手动编排"——必须显式 /build /check /explore。subagents 的 subagent 工具让父 LLM 自己判断什么时候用哪个角色，dteam 缺这个"调度入口"。结果是 dteam 用户必须懂角色工作流，无法自然语言驱动。
- 做什么: 为 dteam 在 P4 入口新增一个 dteam 工具，让主 LLM 能根据用户描述自动选角色、组装 worker、决定串/并/链式执行。模仿 pi-subagents 的 subagent 工具暴露面，但用 dteam 自己的 worker 模式（solo/chain/team）作为底层。

## 范围## 范围

### 包含

- P4 新增 `dteam` 工具：input schema 接受 `{action, goal, agents, mode, ...}`，action 包括 list / plan / run / status
- action=list：列出当前 dteam 角色（从 agents/*.md 读 frontmatter）
- action=plan：根据 goal + 选中的 agents 推断执行计划（单/并/链），不执行
- action=run：执行 plan，调用 worker_create + worker_start
- action=status：查询运行中的 worker（调 worker_status）
- 与 /explore /design /build /check /close 命令的并存：dteam 工具不替代命令，是新的"LLM 调度"路径
- 单元测试：dteam 工具的 list/plan/run/status 4 个 action

### 排除

- 自动编排（task Markdown → chain plan）—— 独立 task，本 task 只暴露调度入口
- TUI 全屏进度流
- intercom 类的子 agent 上抛（由 pubh + EventStream 承接）

### 讨论决策

#### 工具设计

新增 `dteam` 工具，支持 4 个 action：

| Action | 说明 | 输入 | 输出 |
|--------|------|------|------|
| `list` | 列出当前角色 | 无 | 角色列表（name, description, tools） |
| `plan` | 生成执行计划 | goal, agents? | 执行计划（mode, steps, 任务串接方式） |
| `run` | 执行计划 | plan 或 goal + agents | worker 执行结果 |
| `status` | 查询状态 | workerId? | 运行中 worker 状态 |

#### plan 逻辑

- 单 agent → mode=solo
- 多 agent 无依赖 → mode=team（并行）
- 多 agent 有依赖 → mode=chain（串行）
- 默认链：explore → design → build → check → close

#### run 逻辑

- 调用 `worker_create` 创建 worker
- 调用 `worker_start` 启动执行（background 模式）
- 返回 workerId 供 status 查询

#### 实现方案

- 在 `src/P4/index.ts` 新增 `dteam` 工具注册

- 复用现有 `loadAgentRole()`、`wrapWorker()`、`spawnAgent()` 等基础设施
