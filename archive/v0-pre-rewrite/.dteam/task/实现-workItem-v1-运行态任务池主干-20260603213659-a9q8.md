## 目标
- 为什么: dteam 已完成 task/workItem/双层验收/半自动编排的架构定盘，但当前代码仍停留在单层 checklist 和线性角色链上，缺少 workItems 这一运行态调度主语，需要把设计正式落成可执行实现。
- 做什么: 把 dteam 的 A层可校验验收项落成 state.json.workItems[] 运行态任务池主干，完成最小可用实现：WorkItem/RunState 类型、task 双层验收模板、A/B 验收解析、materializeTaskToWorkItems、claimNextWorkItem、checklist projection 以及对应测试。

## 范围- 包含：
  - 新增 `src/P0/workItem.ts`，定义 `WorkItem` / `RunState` / `AttemptRecord` / `HelperRecord` 等类型
  - 更新 `src/P1/task.ts`，把 task 默认模板改为双层验收结构（A 层可校验 / B 层人工裁决）
  - 更新 `src/P3/chainPlanner.ts`，只提取 A 层可校验项进入 plan
  - 更新 `src/P2/contextBuilder.ts`，默认只消费 A 层验收项
  - 新增 `src/P3/workItemPlanner.ts`，实现 `materializeTaskToWorkItems()` / `refreshWorkItemReadiness()` / `claimNextWorkItem()` / `projectChecklistStatus()`
  - 视需要新增 `src/P1/runStateStore.ts`，封装 `state.json` 的结构化 load/save
  - 增加/更新对应测试：`tests/P3/chainPlanner.test.ts`、`tests/P3/workItemPlanner.test.ts`、`tests/unit/contextBuilder.test.ts`，必要时补 `tests/P1/task.test.ts`
  - 保持 `.doc/` 中已定下的 task/workItem/双层验收模型与代码实现一致
- 排除：
  - 本轮不重写完整 Root 调度器闭环
  - 本轮不一次性接完 `help -> resume` 的自动续跑执行
  - 本轮不重做 `/dteam` 面板 UI，只保证数据结构和投影准备好
  - 本轮不处理所有历史研究文档的旧措辞清理
