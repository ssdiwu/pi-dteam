## 目标
- 为什么: dteam 已将验收和调度模型升级为 task 双层验收 + state.json.workItems[] 运行态任务池；现有 P4 界面仍主要围绕线性 checklist 和旧状态文案展示，若不跟进，会造成模型与界面脱节。
- 做什么: 让 P4 界面与 workItem/双层验收模型一致：确认面板区分 A层可校验项和 B层人工裁决项，Worker/进度界面以 workItems/checklistStatus 为数据口径，最终 review 明确把 B层项交还给用户判断。

## 范围- 包含：
  - 确认面板展示双层验收结构：A 层可校验项 / B 层人工裁决项
  - 运行中进度界面以 `workItems[]` / `checklistStatus` 为准，不再假设线性 checklist 就是真相
  - 在合适位置展示 `waiting_help` / `blocked` / `done` / `skipped` 等运行态状态
  - 最终 review / close 前，明确展示 B 层人工裁决项待用户确认
  - 更新 `src/P4/README.md` 与必要测试，确保 P4 文档和行为一致
- 排除：
  - 本 task 不负责重新定义 `workItem` / `RunState` 模型
  - 本 task 不负责实现完整 Root 调度器闭环
  - 本 task 不重做所有 TUI 视觉风格，只做与新模型对齐所必需的界面变化

## 阶段记录### 探索发现

#### 关键复用发现

**P0 已有完整解析器**（`src/P0/workItem.ts`）：

| API | 作用 |
|-----|------|
| `extractAcceptanceModel(content: string)` | 解析 .md 验收条件 → 返回 `{ machine: AcceptanceItem[], human: string[] }` 双层结构 |
| `parseAcId(raw: string)` | 规整 acId（"AC-1" 形式） |
| `WorkItem` / `WorkItemStatus` | 运行态任务池数据模型 |
| `ChecklistStatus` | 面板简视图投影（id/text/status/workerId） |

**这意味着本 task 不需要新建数据模型或解析器**，直接消费 P0 API 即可。

#### 现有 setWidget 渲染能力

- `setWidget(WIDGET_KEY, factory)` 嵌入信息流（不遮输入栏）✅
- factory 返回 `{ render: (width) => string[], invalidate }` ✅
- **不支持 handleInput** ❌（之前几轮踩过的坑）

#### pi 提供的全局快捷键 API

`pi.registerShortcut(key, { description, handler })` 在 `pi` 主函数注册，handler 接收 `ctx`。可通过 `if (!expandedActive) return` guard 实现"面板未开就不响应"。

#### pi-packages-manager 的参考实现

- 用 `ctx.ui.custom()` overlay 模式（会遮输入栏），不适用
- `handleInput` 里直接 `Key.tab` / `Key.shift("tab")` 切 tab——overlay 的能力
- 我们用 `setWidget` + `registerShortcut` 等价实现

### 讨论决策

#### 最终方案

**把 plan 面板作为"特殊 tab"挂到现有 Tab 系统中**：

```
[📋 Plan][🔨 build-w1][🔍 explore-w2]...  ← Tab 栏
─────────────────────────────────
当前选中 Plan tab：显示 Goal + 双层 checklist + 操作提示
当前选中 Worker tab：显示 worker 进度（现有逻辑）
```

**复用现有 setWidget 的同一个 widget**，只是在 Tab 列表和内容渲染里多一个分支。

#### 关键技术决策

1. **Plan tab 位置**：永远在第一位（如果存在），后面按 startTime 排 worker
2. **状态数据**：`pendingPlan: ParsedPlan | null`（模块级），dteam run 完成后写入，用户操作后清空
3. **快捷键**：`pi.registerShortcut("tab"/"shift+tab")` 全局注册 + `if (!expandedActive) return` guard
4. **操作触发**：通过 `/dteam confirm` / `skip` / `cancel` 命令（不在快捷键里，避免与 Tab 切换冲突）
5. **数据源**：`extractAcceptanceModel(mdContent)` 解析当前 .md → `AcceptanceModel`（双层）

#### 权衡取舍

| 选择 | 理由 |
|------|------|
| setWidget + registerShortcut（vs custom overlay） | 用户已明确反对浮层；不遮输入栏 |
| 一个 widget 多 tab（vs 两个独立 widget） | 避免 widget 冲突；统一 Tab 切换 UX |
| Plan tab 用命令触发操作（vs 快捷键 Enter） | 避免快捷键冲突；操作语义明确 |
| 复用 P0 解析器（vs 自写） | P0 API 完备；一致性保证 |

#### 实施步骤

1. **P0 已有 API**：无需改
2. **新建 `src/P4/parseChecklist.ts`**：从 .md 文件读内容 + 调用 `extractAcceptanceModel` 包装为 `ParsedPlan`（含 goal 文本 + machine[] + human[]）
3. **扩展 `worker-widget.ts`**：
   - 加 `pendingPlan: ParsedPlan | null` 状态
   - 加 `setPendingPlan()` / `clearPendingPlan()` 导出函数
   - 改 `buildTabBar`：plan tab 永远在第一位
   - 改 `buildTabContent`：plan tab 渲染 Goal + checklist + 操作
   - 改 `rebuild()`：考虑 pendingPlan 时把 plan 作为第一个 tab
4. **改 `index.ts`**：注册 3 个 `registerShortcut` + 3 个 `/dteam` 子命令
5. **测试**：单测 `parseChecklist`；扩展 `worker-panel.test.ts` 覆盖 plan tab 场景
6. **push**
