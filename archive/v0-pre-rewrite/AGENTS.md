# dteam 扩展包开发规范

## 一、项目概述

dteam 是一个 **Pi 扩展包项目**，本质上是一个**半自动多 worker 编排引擎**。它不是单纯的 prompt 集合，也不是 UI 项目，而是用来把复杂任务转化为**可拆解、可执行、可追踪、可续跑、可交接**工作流的系统。

### 核心定义

- **task**：工作契约（Markdown 格式），定义目标、范围、验收条件，是全局主上下文
- **Root Worker（根 worker）**：唯一编排器 / 主 worker，负责理解目标、拆任务、调度、接收信号、决定是否交人
- **Branch Worker（分支 worker）**：`chain` / `team`，局部协调节点，对上是子 worker，对下是父 worker
- **Leaf Worker（叶子 worker）**：`solo`，最小执行单元，直接读文件、写代码、跑测试、发信号
- **worker tree（worker 树）**：dteam 的执行本体；根 worker 只有一个，分支 worker 可多层嵌套，叶子 worker 是最小执行单元
- **信号**：结构化协作协议（`progress` / `found` / `help` / `blocked`），不是给人看的日志，而是 worker 之间的结构化通信
- **runs/**：运行时现场，保存信号、help、resume 等上下文，支持续跑与审计
- **archive/**：历史知识库，保存完成任务和经验教训

### 基本哲学

- **先把任务讲清楚，再让 worker 去做**
- **AI 没有最终决策权**：dteam 是半自动编排，不是全自动自治系统
- **简单比聪明更重要**：能用最小闭环解决的问题，不引入复杂自治规则

### 目录结构

```
src/
├── P0/             # 原子层：类型、配置、纯函数（不依赖其他层）
├── P1/             # 分子层：服务实现（依赖P0）
├── P2/             # 细胞层：编排模式和上下文构建（依赖P1）
├── P3/             # 组织层：编排决策逻辑（依赖P2）
└── P4/             # 用户接口层：Pi扩展入口和TUI渲染（依赖P3）
```

### 依赖关系

```
P4 → P3 → P2 → P1 → P0
```

## 二、开发流程

1. **先读后写** — 先看文件、搜索现状、确认上下文，再做判断或改动
2. **文档优先** — 修改代码前，先更新对应的 README.md
3. **测试验证** — 修改代码后，运行 `npm test` 验证

## 三、循环防护规则（必须遵守）

### 1. 重复操作检测
如果你发现自己正在：
- 对同一个文件做第 3 次以上的搜索
- 用逐渐增大的参数重复同一个命令（如 grep -A 60 → 70 → 80）
- 连续 3 次说同样的话

**立即停止，换一种方式或问用户。**

### 2. 禁止渐进式参数变化（最重要）
❌ 禁止：grep -A 60 → grep -A 70 → grep -A 80 → ...
✅ 应该：
- 小文件（<500行）→ 直接 read 全文
- 大文件 → 先 read 开头了解结构，再精准 grep 关键词
- 不确定位置 → 问用户，而不是盲目扩大搜索

**一次到位，不行就换方法，绝不渐进扩大。**

### 3. 方法论失败检测
如果你用一种方法尝试了 3 次都没有找到想要的结果：
- **不要再扩大搜索范围**
- 换一种完全不同的方法（比如用 read 而不是 grep，或者问用户具体位置）

### 4. 进度停滞检测
如果你发现：
- 连续 5 个 tool call 都没有获得新的信息
- 连续 3 次操作都卡在同一个问题上

**立即停止，解释原因，问用户下一步怎么做。**

## 四、代码规范

- TypeScript 严格模式
- 文件命名：小驼峰（`taskManager.ts`）
- 函数控制在 50 行以内
- 使用 JSDoc 注释

## 五、Git 规范

- 提交格式遵循 Conventional Commits，描述使用中文
- 运行测试：`npm test`
- 构建检查：`npm run build`

### 提交格式

```
type: 中文描述

[可选正文]
```

类型（type）使用英文关键词：feat、fix、refactor、docs、test、chore、perf、ci、style、build

示例：
- `feat: 添加 worker 并行执行支持`
- `fix: 修复信号丢失问题`
- `refactor: 收敛 task 创建逻辑`
- `docs: 更新 README 规范`
