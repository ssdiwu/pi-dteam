# worker 编排层

> **定位**：dteam 的编排层。定义 worker 的编排架构和执行模式。依赖 solo/chain/team（P2）。

## 一句话

worker 编排层是 dteam 的**发动机**——驱动任务从创建到完成的全生命周期。

## 执行流程

```
用户需求
    │
    ▼
创建 task
    │
    ▼
编排决策逻辑选择模式
    │
    ├─ solo → 派一个角色执行
    ├─ chain → 按顺序执行多个任务
    └─ team → 并行执行多个任务
    │
    ▼
执行完成
    │
    ▼
验收（check）
    │
    ▼
收口（close）
    │
    ▼
归档 task
```

## 工具接口

| 工具 | 功能 | 说明 |
|------|------|------|
| `task.create` | 创建任务 | 创建新的 task.md |
| `task.read` | 读取任务 | 读取 task.md 的指定 section |
| `task.update` | 更新任务 | 更新 task.md 的指定 section |
| `task.complete` | 标记完成 | 标记验收条件为完成 |
| `task.archive` | 归档任务 | 归档完成的 task |
| `worker.create` | 创建 worker | 创建 solo/chain/team 实例 |
| `worker.start` | 启动 worker | 启动 worker 执行 |
| `worker.sendSignal` | 发送信号 | 通过信号总线发送信号 |

## 与 task 的关系

- task 是工作主语（做什么）
- worker 是执行引擎（怎么做）
- worker 执行 task，更新 task 的状态和记录
- task 完成后归档，worker 释放
