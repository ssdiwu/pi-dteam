# 角色定义

> **定位**：dteam 的五个核心执行角色及其协作模型。

## 一句话

角色是 dteam 的**执行者**——每个角色有明确的职责、边界和协作方式。

## 五角色模型

```
┌─────────────────────────────────────────────────────────────────┐
│                        P2 角色执行层                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   ┌──────────┐    ┌──────────┐    ┌──────────┐                  │
│   │  explore │───▶│  design  │───▶│  build   │                  │
│   │  探索者   │    │ 方案制定  │    │  实现者   │                  │
│   └──────────┘    └──────────┘    └──────────┘                  │
│        │               │               │                        │
│        │               ▼               ▼                        │
│        │          ┌──────────┐    ┌──────────┐                  │
│        └─────────▶│  check   │◀───│  close   │                  │
│                   │  验收者   │    │  收口者   │                  │
│                   └──────────┘    └──────────┘                  │
│                                                                 │
│   ════════════════════════════════════════════════════════════  │
│   build 是唯一写线程 | 其他角色只读                             │
│   ════════════════════════════════════════════════════════════  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 角色职责速览

| 角色 | 中文名 | 核心职责 | 写权限 |
|------|--------|----------|--------|
| **explore** | 探索者 | 侦察现状、发现约束、输出探索报告 | ❌ 只读 |
| **design** | 方案制定者 | 分析需求、制定方案、输出计划文档 | ❌ 只读 |
| **build** | 实现者 | 执行计划、编写代码、实现功能 | ✅ **唯一写线程** |
| **check** | 验收者 | 验证产出、检查质量、确认完成 | ❌ 只读 |
| **close** | 收口者 | 整理归档、记录经验、关闭任务 | ❌ 只读 |

## 核心设计原则

### 1. 单一写线程

```
┌──────────────────────────────────────────────────────┐
│  写冲突防护                                           │
│                                                      │
│  explore ─┐                                          │
│  design  ─┤──▶ ❌ 无写权限                            │
│  check   ─┤                                          │
│  close   ─┘                                          │
│                                                      │
│  build ────▶ ✅ 唯一写线程                            │
│                                                      │
│  效果：消除并发写冲突，简化状态一致性问题              │
└──────────────────────────────────────────────────────┘
```

**为什么是 build？**
- 实现阶段写操作最频繁（代码、配置、测试）
- 集中写权限便于实现原子提交和回滚
- 其他角色的产出通过 build 审核后落地

### 2. 非线性信息流

角色间的信息流**不是严格线性的**，而是按需跳转：

```
正常路径：    explore → design → build → check → close
                                    ↑           │
短路回退：    design ◀──────────────┘           │
                                    ↑           │
探索回退：    explore ◀─────────────┘           │
                                                │
闭环收口：    close ─────────────────────────────┘
```

**信息流由主 worker（solo/chain/team）控制**：
- 子代理给信号给主 worker
- 主 worker 下发策略
- 信息流是**非线性的**，explore 可以给 design、build、check 等

**触发回退的场景：**

| 从 | 到 | 触发条件 |
|----|-----|---------|
| build | design | 实现发现方案不可行，需要调整设计 |
| check | build | 验收发现问题，需要修复 |
| check | explore | 验收发现约束未被考虑，需要重新探索 |
| close | check | 归档前最终确认发现遗漏 |

### 3. 角色边界清晰

每个角色：
- **独立定义**：职责、输入、输出、边界条件
- **可独立执行**：不依赖其他角色的内部状态
- **通过接口协作**：只通过约定的文档/状态进行交互

## 信息流转协议

### 角色产出物

| 角色 | 产出物 | 产出位置 |
|------|--------|----------|
| explore | 探索报告 | task.md 的"探索发现"section |
| design | 方案计划 | task.md 的"讨论决策"section |
| build | 代码变更 + 执行报告 | 代码库 + task.md 的"执行记录"section |
| check | 验收报告 | task.md 的"验收条件"更新 |
| close | 归档记录 | task.md 归档到 .dteam/archive/ |

### 状态标记

每个角色执行后，更新 task 的状态：

```
task 状态机：
  todo → InSpec → InProgress → Done
              ↑           │
              │           └── (check 回退)
              │
              └── (explore 完成后进入 InSpec)
```

## 委托与并行

### team 并行执行

当任务满足以下条件时，可委托 team 并行执行：
- 需要修改 3+ 文件
- 子任务间依赖度低
- 跨模块变更

```
                    ┌─────────────────┐
                    │      build      │
                    │  (协调者/汇总者) │
                    └────────┬────────┘
                             │
              ┌──────────────┼──────────────┐
              ▼              ▼              ▼
         ┌────────┐    ┌────────┐    ┌────────┐
         │ task1  │    │ task2  │    │ task3  │
         └────────┘    └────────┘    └────────┘
              │              │              │
              └──────────────┴──────────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │      build      │
                    │    (汇总结果)    │
                    └─────────────────┘
```
