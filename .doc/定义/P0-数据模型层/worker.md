# worker 数据模型

> **定位**：dteam 的执行单元。通过 solo/chain/team 三种模式，在高效与有效之间取得平衡。

## 一句话

worker 是 dteam 的执行引擎——通过 solo、chain、team 三种模式，实现任务的高效执行。

## 核心特征

| 特征 | 值 |
|------|-----|
| 类型 | 3种：solo / chain / team |
| 通信 | 信号机制（13种信号） |
| 嵌套 | 最大4层 |

## 三种模式

| 模式 | 定位 | 适用场景 |
|------|------|----------|
| **solo** | 有效 | 小任务（<100行，<3文件） |
| **chain** | 综合 | 有冲突的串行任务 |
| **team** | 高效 | 可并行的任务（优先选择） |

## 决策优先级

```
team > solo > chain
```

## 模式详情

### solo（单任务模式）

**定义**：派一个角色执行一个任务。

**三种子模式**：

| 子模式 | 适用场景 | 流程 |
|--------|---------|------|
| `simple` | 极简改动（1-2行） | 直接执行 |
| `maker-checker` | 标准任务（默认） | 执行 → 检查 |
| `adaptive` | 复杂无冲突 | 规划 → 执行 → 评估 |

**适用场景**：小任务（<100行，<3文件）

### chain（串行模式）

**定义**：按顺序执行多个任务，前一个完成才执行下一个。

**适用场景**：
- 任务之间有依赖关系
- 需要按步骤推进
- 有冲突的串行任务

### team（并行模式）

**定义**：同时派多个角色并行执行多个任务。

**适用场景**：
- 多个任务无依赖关系
- 需要同时修改多个文件
- 可并行的任务（优先选择）

## 嵌套规则

| 规则 | 说明 |
|------|------|
| solo 不能嵌套 | 叶子节点，不可再分 |
| chain steps 可嵌套 | steps 中可包含 solo 和 team |
| team tasks 可嵌套 | tasks 中可包含 solo 和 chain |
| 最大深度四层 | 防止过度嵌套 |

## 信号机制

worker 通过信号总线进行即时通信：

| 类别 | 信号 | 说明 |
|------|------|------|
| 状态报告 | progress, blocked, found | 子代理报告当前状态 |
| 协调请求 | help | 子代理请求外部帮助 |
| 策略恢复 | retry, adjust, switch, replan, send, learn | 自动恢复机制 |

详见 [信号类型.md](./信号类型.md)

## 不变量

1. solo 只能有一个角色和一个任务
2. chain steps 不能为空
3. team tasks 不能为空
4. 嵌套深度不超过四层

## 与其他概念的关系

| 概念 | 关系 | 说明 |
|------|------|------|
| task | worker 执行 task | task 是工作主语，worker 是执行引擎 |
| 角色 | worker 使用角色 | 角色定义在 P2-角色执行层 |
| 信号 | worker 通过信号通信 | 信号定义在 信号类型.md |
