# 信号类型

> **定位**：dteam 信号总线中所有信号类型的完整定义——语义、使用场景和代码来源。

## 一句话

信号是 worker 内部的**无线电频道**——每种信号类型代表一种语义，子代理通过它报告状态、请求帮助、分享发现。

## 信号类型全景

### 信号分类（4大类）

| 类别 | 信号 | 说明 |
|------|------|------|
| **状态报告** | progress, blocked, found | 子代理报告当前状态 |
| **协调请求** | help | 子代理请求外部帮助 |
| **策略恢复** | retry, adjust, switch, replan, send, learn | 自动恢复机制 |
| **经验沉淀** | learn | 失败经验记录 |

### 完整信号类型（13种）

| # | 信号 | 谁发 | 含义 | 使用场景 |
|---|------|------|------|---------|
| 1 | `progress` | 任意 | 进度更新 | 子代理报告执行进度、阶段性成果 |
| 2 | `blocked` | 任意 | 遇到阻塞 | 子代理无法继续执行，需要外部介入 |
| 3 | `found` | 子代理 | 发现有用信息 | 子代理发现对其他 worker 可能有价值的信息 |
| 4 | `help` | 任意 | 请求协助 | 子代理需要其他角色或用户的帮助 |
| 5 | `retry` | 任意 | 重试任务 | 策略链第一步：重试当前任务 |
| 6 | `adjust` | 任意 | 调整策略 | 策略链第二步：调整任务描述后重试 |
| 7 | `switch` | 任意 | 切换资源 | 策略链第三步：切换到 fallback 模型 |
| 8 | `replan` | 任意 | 重新规划 | adaptive 模式中触发重新规划 |
| 9 | `learn` | 任意 | 记录经验 | 策略链最后一步：记录失败经验 |
| 10 | `send` | worker | 发送子代理信号 | 策略链第四步：给子代理发送 terminate 信号 |
| 11 | `claimed` | 子代理 | 任务认领 | 子代理认领任务 |
| 12 | `released` | 子代理 | 任务释放 | 子代理释放任务 |
| 13 | `done` | 子代理 | 任务完成 | 子代理完成任务 |

## 信号详细说明

### 1. progress — 进度更新

**语义**：子代理正在执行，报告阶段性进展。

**使用场景**：
- maker-checker 模式中，maker/checker 完成各自任务后发出
- adaptive 模式中，planner/executor/evaluator 完成后发出
- chain 模式中，每步完成后发出

**payload 结构**：
```typescript
{ output: string }       // 执行结果
{ plan: string }         // 规划结果
{ evaluation: string }   // 评估结果
```

### 2. blocked — 遇到阻塞

**语义**：子代理无法继续执行，原因是环境/依赖/权限等外部问题。

**使用场景**：
- spawnAgent 返回错误且策略链无法恢复时
- maker/checker/planner/executor/evaluator 任一执行失败时
- team 的 worker 执行抛出异常时

**与 `help` 的区别**：`blocked` 表示"我搞不定了"；`help` 表示"我需要别人帮一下"。

### 3. found — 发现有用信息

**语义**：子代理在执行过程中发现了对其他 worker 有价值的信息。

**使用场景**：
- explorer 发现了相关代码位置
- 子代理发现了潜在的 bug 或改进点
- 搜索过程中找到关键文档

### 4. help — 请求协助

**语义**：子代理需要其他角色或用户的帮助才能继续。

**使用场景**：
- chain 某步执行失败，需要链级别的干预
- 子代理需要其他 worker 的中间结果
- 遇到歧义，需要用户做决策

**与 `blocked` 的区别**：`help` 仍有解决意愿，只是缺资源/信息；`blocked` 是完全卡住。

### 5-10. 策略恢复信号

**语义**：worker 策略链的自动恢复机制。

**策略链流程**：
```
retry → adjust → switch → send → learn
 ↓       ↓        ↓        ↓       ↓
重试   调整task  换模型  终止子代理  记录经验
```

### 11-13. 任务生命周期信号

**语义**：任务的认领、释放、完成。

## 信号流转示意

```
worker 策略链（agent 执行失败时）：
  retry → adjust → switch → send → learn
   ↓       ↓        ↓        ↓       ↓
  重试   调整task  换模型  终止子代理  记录经验

chain 双向沟通：
  solo --help/blocked--> chain
  chain --adjust-------> solo

team 内部协调：
  子代理 --progress/blocked/found/help--> owner
  owner 决定是否重建 worker / 调整策略 / 升级人工
```

## 使用注意事项

1. **信号不可变**——一旦发出，不可修改或撤回
2. **TTL 过期**——默认 5 分钟后信号从 query 结果中消失（历史记录仍在）
3. **类型安全**——emit/on/query 均使用 TypeScript 类型约束
4. **进程内通信**——信号总线不走网络，生命周期与 team 实例绑定
