# 编排决策逻辑

> **定位**：dteam 的编排层。指导 AI 如何选择 solo/chain/team 三种编排模式。依赖 solo/chain/team（P2）。

## 一句话

编排决策是 dteam 的**调度器**——根据任务特征选择最合适的执行模式。

## 决策流程

```
用户需求
    │
    ▼
评估任务特征
    │
    ├─ 可并行？ ──→ team
    │
    ├─ 有冲突？ ──→ chain
    │
    └─ 小任务？ ──→ solo
```

## 决策优先级

```
team > solo > chain
```

**理由**：
- team 最高效（并行执行）
- solo 最简单（单任务）
- chain 是综合模式（串行+并行混合）

## 决策矩阵

| 条件 | 推荐模式 | 原因 |
|------|----------|------|
| 任务可并行执行 | **team** | 最高效 |
| 任务有依赖冲突 | **chain** | 综合性 |
| 任务<100行且<3文件 | **solo** | 最简单 |

## solo 的三种子模式决策

| 条件 | 推荐子模式 | 原因 |
|------|------------|------|
| 极简改动（1-2行） | **simple** | 直接执行 |
| 标准任务（默认） | **maker-checker** | 执行+检查 |
| 复杂但无冲突 | **adaptive** | 规划+执行+评估 |

## 决策示例

### 场景1：5个独立小功能

**任务特征**：
- 5个功能无依赖关系
- 每个功能<100行

**决策**：team（并行执行）

```json
{
  "mode": "team",
  "tasks": [
    { "type": "solo", "agent": "build", "task": "功能1" },
    { "type": "solo", "agent": "build", "task": "功能2" },
    { "type": "solo", "agent": "build", "task": "功能3" },
    { "type": "solo", "agent": "build", "task": "功能4" },
    { "type": "solo", "agent": "build", "task": "功能5" }
  ]
}
```

### 场景2：复杂的设计决策

**任务特征**：
- 需要多轮讨论
- 有冲突的方案

**决策**：chain（第一轮team讨论，第二轮solo总结）

```json
{
  "mode": "chain",
  "steps": [
    {
      "mode": "team",
      "tasks": [
        { "type": "solo", "agent": "explore", "task": "方案A探索" },
        { "type": "solo", "agent": "explore", "task": "方案B探索" }
      ]
    },
    { "agent": "design", "task": "方案总结与决策" }
  ]
}
```

### 场景3：修复一个bug

**任务特征**：
- 单一任务
- <100行

**决策**：solo（maker-checker模式）

```json
{
  "mode": "solo",
  "agent": "build",
  "task": "修复登录页面logo尺寸错误",
  "sub_mode": "maker-checker"
}
```

## 嵌套规则

| 规则 | 说明 |
|------|------|
| solo 不能嵌套 | 叶子节点，不可再分 |
| chain steps 可嵌套 | steps 中可包含 solo 和 team |
| team tasks 可嵌套 | tasks 中可包含 solo 和 chain |
| 最大深度四层 | 防止过度嵌套 |

## 与 worker 的关系

编排决策逻辑指导 worker 的使用：
- worker 是执行引擎
- 编排决策逻辑是调度器
- 根据任务特征选择最合适的 worker 模式
