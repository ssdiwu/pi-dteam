# 术语与文风规范

> **定位**：dteam 的术语口径和写作惯例。

## 核心术语

| 术语 | 英文 | 定义 |
|------|------|------|
| task | task | 工作主语对象，一个完整的功能或任务 |
| worker | worker | 执行单元，通过 solo/chain/team 三种模式执行任务 |
| solo | solo | 单任务执行模式 |
| chain | chain | 串行执行模式 |
| team | team | 并行执行模式 |
| 角色 | role | 执行角色，包括 explore/design/build/check/close |
| 信号 | signal | worker 之间的即时通信机制 |

## 命名规范

### 文件命名

- task 文件：`{name}-{timestamp}-{random4}.md`
- 文档文件：`{名称}.md`
- 目录名：使用中文或英文，保持一致

### 变量命名

- 常量：大写下划线（`MAX_TOKENS`）
- 变量：小驼峰（`taskId`）
- 类型：大驼峰（`TaskType`）
- 接口：大驼峰，以 I 开头（`ITaskConfig`）

## 文风规范

### 文档结构

- 每个文档必须有 frontmatter
- 使用 Markdown 格式
- 使用中文撰写
- 技术术语使用英文

### 语言风格

- 简洁明了
- 避免冗余
- 使用主动语态
- 避免口语化

### 代码示例

- 使用 TypeScript 类型定义
- 使用 JSON 示例配置
- 使用 Markdown 代码块
